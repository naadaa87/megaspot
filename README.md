# 메가스팟 MEGASPOT — 홈페이지 · 플랫폼 (Cloudflare Pages 배포용)

큰 모임에 맞는 공간을 찾다. 초대형 공간을 찾고·예약하고·모임을 여는 플랫폼 **메가스팟**의 홈페이지입니다. 직영 공간 **메가스팟 건대 1호**(190평)·**건대 2호**(400평, 2026-11-13 오픈)의 상세·예약·후기와, 플랫폼 기능(모임 홍보·참가자 모집, 호스트 입점·공간 등록 신청, 등록 공간 소개, 배너 광고)이 들어 있는 정적 사이트 + Cloudflare Pages Functions(API) + D1 데이터베이스 구성입니다.

터미널 없이 **GitHub 웹 화면과 Cloudflare 대시보드만으로** 배포할 수 있게 만들었습니다.

## 2. 배포 순서 (약 15분)

### ① GitHub 저장소 만들기
1. github.com → **New repository** → 이름 예: `megaspot` → Public/Private 아무거나 → Create.
2. 저장소 화면에서 **Add file → Upload files** 를 누르고, 이 폴더 안의 **모든 파일과 폴더를 그대로** 끌어다 놓습니다. (`index.html`이 저장소 최상위에 있어야 합니다.)
   - 파일이 250개가 넘어(약 33MB) 웹 화면의 한 번 업로드 한도(100개)를 넘습니다. 업로드용 zip을 풀면 나오는 폴더 네 개(1_pages, 2_photos, 3_scenes, 4_views-aerial)를 차례로, 각 폴더 **안의 내용**을 끌어다 놓아 올리면 됩니다.
3. **Commit changes** 를 누릅니다.

### ② Cloudflare Pages 연결
1. dash.cloudflare.com → **Workers & Pages → Create → Pages → Connect to Git** → 위 저장소 선택.
2. 빌드 설정은 **모두 비워 둡니다.**
   - Framework preset: `None`
   - Build command: (비움)
   - Build output directory: `/` (또는 비움)
3. **Save and Deploy** → 1분쯤 뒤 `https://megaspot.pages.dev` 같은 주소가 생깁니다. 이 단계에서 이미 모든 페이지·3D·도면이 동작합니다.
   - 아직 데이터베이스가 없으므로 문의·후기 폼은 자동으로 **체험 모드**(문의 내용 복사·문자·이메일 전송 안내)로 동작합니다.

### ③ D1 데이터베이스 만들기
1. Cloudflare 대시보드 → **Storage & Databases → D1 SQL Database → Create** → 이름 `megaspot-db` → Create.
2. **표(테이블)는 만들지 않아도 됩니다.** 홈페이지 서버가 처음 요청을 받을 때 `schema.sql`에 적힌 표 12개(문의·입점·예약·후기·일정·변경 기록·회원·로그인·로그인 시도·관리자 로그인·견적·체크리스트)를 스스로 만듭니다. 이미 있는 표와 데이터는 그대로 둡니다.
   - 직접 만들고 싶다면 DB 화면의 Studio(또는 Console)에 `schema.sql` 전체를 붙여 넣고 **모든 문장을 실행**합니다. Studio의 Run 버튼은 커서가 있는 문장 하나만 실행할 수 있으니, 전체를 선택한 뒤 실행하세요.

### ④ Pages 프로젝트에 DB·운영자 키 연결
1. Workers & Pages → `megaspot` 프로젝트 → **Settings → Bindings → Add → D1 database**
   - Variable name: **`DB`** (대문자, 정확히)
   - D1 database: `megaspot-db`
2. 같은 Settings → **Variables and Secrets → Add**
   - Variable name: **`ADMIN_KEY`** · Type: **Secret** · Value: 관리자 페이지 비밀번호(영문·숫자·기호를 섞어 12자 이상, 따로 안전하게 보관)
   - 이 값이 없으면 `/admin/`에 로그인할 수 없습니다. 비밀번호를 바꾸려면 같은 곳에서 값을 고친 뒤 다시 배포합니다.
3. **Deployments 탭 → 최신 배포의 ⋯ → Retry deployment** (바인딩은 재배포 후 적용됩니다.)

### ⑤ 확인
- `https://(내주소)/api/health` 에 접속해 `"db":true`, `"tables_ok":true`, `"admin_key":true` 세 가지가 보이면 연결 완료입니다. (`tables_ok`가 false면 아무 페이지나 한 번 새로 고친 뒤 다시 확인하세요. `admin_key`가 false면 ④-2를 다시 확인하고 재배포합니다.)
- `https://(내주소)/admin/` 에서 ADMIN_KEY 값으로 로그인하면 관리자 화면이 열립니다.
- `/inquiry/` 에서 시간·날짜·인원을 고르고 **예약신청하기**로 한 건 보내 본 뒤, 운영자 페이지 문의함에 파란 **예약 신청** 표시와 함께 들어오는지 확인합니다.
- `https://(내주소)/signup/` 에서 테스트 계정으로 가입 → 마이페이지가 열리고, 그 상태로 예약을 신청하면 마이페이지 '내 문의'와 운영자 문의함(파란 '회원' 표시)에 함께 나타나는지 확인합니다. 테스트 계정은 마이페이지 맨 아래 '회원 탈퇴'로 지웁니다.

### ⑥ 도메인 연결(선택)
Pages 프로젝트 → **Custom domains → Set up a custom domain**. 현재 대표 주소는 `https://megaspot.kr`이고, `sitemap.xml`·`rss.xml`·`robots.txt`, 각 페이지 `<link rel="canonical">`·OG 주소·구조화 데이터가 모두 이 주소로 되어 있습니다. 도메인을 다시 바꾸면 `tools/build_site.py`의 `SITE_URL`을 고쳐 다시 빌드합니다. `megaspot.pages.dev`와 `www.megaspot.kr`로도 같은 화면이 열리지만, 각 페이지가 대표 주소를 canonical로 알려 주므로 검색에는 megaspot.kr 주소로 모입니다.

## 3. 운영 방법

### 연락처·사업자 정보 바꾸기 — `assets/js/site.js` 맨 위 `CONFIG`
```js
phone: '010-2384-9580',          // 대표 상담 번호
email: 'spaceblank0100@gmail.com', // 대표 이메일
kakaoChannel: 'https://pf.kakao.com/_LnxbmX/chat', // 메가스팟 전용 카카오톡 채널 1:1 채팅 (2026-10-17 변경). 비우면 카카오톡 버튼이 숨겨집니다
kakaoNote: '메가스팟 전용 카카오톡 채널로 1:1 채팅이 바로 열립니다.',
hours: '평일 10:00–19:00 …',
companyName: '', bizNo: '', ceo: '',  // 사업자 상호·등록번호·대표자 — 입력하면 푸터에 표시됩니다
```
한 곳만 바꾸면 모든 페이지의 전화·이메일·카카오톡 링크·푸터가 함께 바뀝니다.

**카카오톡 문의 채널** — 아래 위치에 QR코드·버튼·링크가 들어가 있습니다.
- 모든 페이지 푸터(QR코드 + 링크), 모바일 메뉴(카카오톡 문의 버튼)
- 건대 상세: 맨 위 '카카오톡 문의' 버튼, 예약·문의 섹션의 바로 연락 카드(QR코드·버튼·전화·이메일)
- 문의 페이지 오른쪽 바로 연락 카드, 문의 완료 화면의 '카카오톡으로 보내기'(문의 내용을 복사하고 채널을 엽니다)
- 소개·요금 안내·이용 안내(FAQ 포함) 페이지의 문의 버튼, 개인정보처리방침의 카카오톡 상담 항목

QR 이미지는 `assets/img/brand/kakao-qr.svg` 입니다. **채널 주소를 바꾸면 QR 이미지도 새 주소로 다시 만들어 같은 이름으로 교체**해야 합니다(CONFIG만 바꾸면 버튼·링크는 바뀌지만 QR 그림은 그대로입니다).

### 관리자 페이지 (`/admin/`)
홈페이지 머리말·푸터 없이 따로 열리는 관리 화면입니다. `ADMIN_KEY` 값으로 로그인하면 12시간(‘7일 유지’ 체크 시 7일) 동안 로그인이 유지되고, 왼쪽 아래 **로그아웃**으로 끝냅니다. 검색엔진에는 나오지 않습니다.

5. 고객이 공간을 먼저 보고 싶어 하면 문의 상세의 **+ 답사 일정 추가**(전화·카톡으로 처음 받은 문의라면 문의 직접 등록 때 ‘현장답사 일정도 함께 등록’)로 일정을 넣고, **안내문 복사**로 주소·주차 안내를 보냅니다. 홈페이지에서 ‘현장답사를 먼저 하고 싶어요’를 체크한 신청은 **일자별 현장답사** 맨 위 ‘조율이 필요한 답사 요청’에 쌓이니, 통화해 시간을 정하고 ‘일정 잡기’를 누르세요. 답사가 끝나면 완료와 결과(예약 진행·고민 중·다른 곳 선택)를 남깁니다.
6. 주간 회의나 현장 준비 때는 **일자별 예약**에서 ‘이번 주’ 또는 ‘다음 달’을 눌러 확정·후보 일정을 날짜별로 보고, 같은 날 후보가 겹친 날(노란 표시)부터 정리합니다. 필요하면 인쇄해 둡니다.
7. 네이버·스페이스클라우드·카카오톡으로 들어온 문의는 대시보드의 **예약 채널 바로가기**로 각 관리자 화면을 열어 확인하고, **문의 직접 등록**에서 경로를 골라 남겨 두면 대시보드 **문의 경로**에서 채널별 성과를 볼 수 있습니다.
8. 행사 뒤 일자별 예약(또는 예약 관리)에서 **이용 완료** → 보증금 반환·후기 요청을 체크합니다. 고객은 예약번호와 휴대폰 뒷 4자리로 후기를 쓸 수 있습니다.

### 회원 (가입·로그인·마이페이지)
- 주소: 회원가입 `/signup/`, 로그인 `/login/`, 마이페이지 `/mypage/`. 모든 페이지 머리말 오른쪽과 모바일 메뉴에 '로그인'(로그인 후에는 '마이페이지') 링크가 있습니다. 회원 페이지는 검색에 나오지 않게 `noindex`로 두었습니다.
- 가입: 이메일·비밀번호(8자 이상, 영문+숫자)·이름·휴대폰 번호, 소속(선택). 필수 동의는 만 14세 이상·이용약관·개인정보 수집·이용, 선택 동의는 마케팅 수신입니다. 가입하면 바로 로그인됩니다. (이메일 인증 메일은 보내지 않습니다 — 아래 '나중에 붙일 수 있는 것' 참고)
- 회원이 로그인한 상태로 문의하면 이름·소속·연락처·이메일이 자동으로 채워지고, 문의가 회원에 연결돼 **마이페이지 '내 문의'에 진행 상태**(문의 접수 → 조건 확인 → 견적 발송 → 결제 대기 → 예약 확정 → 이용 완료)가 표시됩니다. 운영자 페이지에서 문의 상태를 바꾸면 회원 화면에도 그대로 반영됩니다.
- 가입하지 않아도 문의는 예전과 똑같이 할 수 있습니다. 비회원이 보낸 문의는 마이페이지에 나오지 않습니다.
- 마이페이지에서 회원 정보 수정, 비밀번호 변경, 회원 탈퇴(비밀번호 확인 후 회원 정보 즉시 삭제)를 할 수 있습니다.
- **비밀번호 찾기**: 로그인 화면의 '비밀번호를 잊으셨나요?'는 카카오톡·이메일 문의로 안내합니다. 운영자는 가입 이름·휴대폰 번호로 본인인지 확인한 뒤 **운영자 페이지 → 회원 → 임시 비밀번호 발급**을 눌러 나온 10자리 임시 비밀번호를 알려 주고, 로그인 후 마이페이지에서 바꾸도록 안내합니다.
- 운영자 페이지 **회원** 탭: 회원 목록(가입일·최근 로그인·연락처·소속·문의 건수·마케팅 수신 여부), 검색, 임시 비밀번호 발급, 이용 제한/해제.
- 보안: 비밀번호는 PBKDF2-SHA256(10만 회, 무작위 솔트)로 바꿔 저장해 운영자도 원래 비밀번호를 볼 수 없습니다. 로그인은 자바스크립트가 읽을 수 없는 보안 쿠키(HttpOnly·Secure·SameSite)로 30일 유지되고, 다른 사이트에서 회원 기능을 대신 호출하는 요청은 막습니다. 같은 이메일로 15분 안에 8번 틀리면 15분간 로그인을 막습니다. 비밀번호를 바꾸거나 임시 비밀번호를 발급하면 다른 기기의 로그인은 모두 풀립니다.
- 따로 설정할 것은 없습니다. 위 ③④(D1 연결·`schema.sql` 실행)만 되어 있으면 회원 기능이 켜지고, DB가 연결되지 않은 동안에는 가입·로그인 화면에 '준비 중' 안내가 나오며 문의는 계속 체험 모드로 받습니다.
- 나중에 붙일 수 있는 것: 가입 확인 메일·비밀번호 재설정 메일(메일 발송 서비스 연결 필요), 카카오·네이버 간편 로그인(각 개발자 센터에 앱 등록 필요), 회원 전용 혜택.

### 온라인 결제 — 페이앱 (이용권 구매 `/products/`)

고객이 `/order/`에서 주문하면 서버가 금액을 다시 계산하고 페이앱 REST API로 결제를 요청합니다. 응답의 HTTPS `payurl`로 이동하며, 서버가 검증한 결제통보만 주문·예약을 확정합니다. 기존 주문 내역은 유지됩니다.

**Cloudflare에 키 넣는 방법**
1. [페이앱 판매자 관리자](https://seller.payapp.kr/c/apiconnect_info) → **설정메뉴 → 연동정보**에서 판매자 ID·연동 KEY·연동 VALUE·결제 KEY(requestkey)를 확인합니다.
2. [Cloudflare](https://dash.cloudflare.com/) → **Workers & Pages → megaspot → Settings → Variables and secrets**를 엽니다. 환경은 **Production**을 선택합니다.
3. **Add**를 눌러 아래 네 항목을 모두 **Secret**으로 저장합니다. **Add variable**로 한 번에 추가할 수 있습니다. 값에는 키만 붙여 넣으세요(‘복사’ 등의 문구·공백 제외).

| Variable name | 페이앱에서 가져올 값 | Type |
| --- | --- | --- |
| `PAYAPP_USERID` | 로그인하는 판매자 아이디 | Secret |
| `PAYAPP_LINKKEY` | 연동 KEY | Secret |
| `PAYAPP_LINKVAL` | 연동 VALUE | Secret |
| `PAYAPP_REQUESTKEY` | 결제 KEY (`requestkey`) | Secret |

4. **Save** 후 새 코드를 배포합니다. 변수 변경도 다음 배포부터 적용됩니다. Git 저장소의 `main`에 변경 사항을 올리거나 **Deployments → 최신 배포 → More actions → Retry deployment**를 사용하세요. 예전 이니시스 코드를 재배포해서는 페이앱이 연결되지 않습니다.
5. `https://megaspot.kr/api/pay/config`에서 `provider: "payapp"`, `configured: true`, `enabled: true`를 확인합니다. 키가 없거나 `PAYAPP_ENABLED=0`이면 고객에게 결제 준비 중 안내가 보이고 결제 요청은 차단됩니다.
6. 실제 결제 승인·취소는 운영자가 직접 확인합니다. 페이앱은 현재 가맹점 키를 쓰므로 결제창이 열리면 실결제입니다. 가짜 테스트 완료 처리는 제공하지 않습니다.

- 키는 Cloudflare 서버 Secret에만 저장하며 HTML·JavaScript·Git에 넣지 않습니다. Production 키를 Preview 환경에 복사하지 마세요.
- 결제 통보 URL은 `https://megaspot.kr/api/pay/feedback`이고, 요청마다 서버가 전달하므로 페이앱의 **공통 통보 URL은 비워 두어도 됩니다**. 이미 다른 시스템에서 쓰는 공통 URL은 변경하지 않습니다.
- 결제 후 이동 URL은 `https://megaspot.kr/api/pay/return?oid=주문번호`입니다. 이 주소로 돌아온 것만으로는 결제가 완료되지 않습니다.
- 계정에서 사용 가능한 결제 수단만 페이앱 결제창에 표시됩니다. 결제 수단 추가·활성화는 페이앱 판매자 관리자에서 확인합니다.
- D1 `DB` 바인딩은 유지합니다. `schema.sql`의 `payapp_payments`(주문·거래번호·검증 nonce), `payapp_refunds`(취소 거래별 환불 금액) 표는 첫 API 요청에서 자동 생성됩니다.

**운영자가 1,000원으로 결제·취소 확인하기**
- 링크: `https://megaspot.kr/order/?product=payapp-check-1000`
- 실제 1,000원(부가세 포함)이 승인됩니다. 일반 상품 목록에는 표시하지 않으며, 수량·이용일·옵션·문의번호를 조작해도 서버에서 1건 1,000원으로 계산하고 예약을 만들지 않습니다.
- 본인 정보로 결제 → 페이앱 판매자 관리자의 **결제현황**에서 해당 주문번호의 1,000원 거래를 **전액 취소** → 메가스팟 결과 화면의 **취소 반영 확인**을 누릅니다.
- 완료 기준: “1,000원 결제 취소가 확인되었습니다”와 취소 금액 1,000원 표시. 실제 승인·취소 내역을 기록하므로 가짜 테스트(`test=1`)로 처리하지 않습니다.

**결제·취소 결과 처리**
- 판매자 아이디·연동 KEY·VALUE·결제 KEY 해시·통보 시각·주문 nonce·거래번호·금액을 검증합니다. 검증 실패는 성공 응답을 보내지 않습니다.
- 완료 통보(`pay_state=4`)가 오면 주문이 `paid`로 바뀌고 이용권 예약과 연결 문의가 확정됩니다. 중복·동시 통보는 D1 트랜잭션과 결정적인 예약번호로 한 번만 처리합니다.
- 가상계좌를 사용하게 될 경우 `10`은 입금 대기로 표시하고, `4`(입금 완료)에서만 예약을 확정합니다.
- 고객 화면은 결과 수신 지연에 대비해 약 30초간 자동 재확인합니다. 진행 중일 때 재결제 버튼을 제공하지 않습니다.
- 환불은 **페이앱 판매자 관리자**에서 실제 취소하세요. 전체 취소(`9`, `64`)는 주문을 환불 처리하고 연결 예약을 취소합니다. 부분 취소(`70`, `71`)는 원거래 금액·번호를 검증한 뒤 환불 금액만 기록하고 예약은 유지합니다. 취소된 주문은 늦은 완료 통보로 되살아나지 않습니다.
- 관리자 주문 목록은 환불 금액과 남은 금액을 보여 주며, 페이앱 주문 상태는 수동 변경할 수 없습니다. 기존 PG 주문의 수동 기록 기능은 유지됩니다.
- 전체 환불 뒤 달력에 운영자가 직접 만든 마감·대기는 지우지 않습니다. 필요한 경우 해당 일정은 직접 확인하세요.

참고: [페이앱 공식 API 매뉴얼](https://www.payapp.kr/dev_center/dev_center01.html), [Cloudflare Pages Secret 설정](https://developers.cloudflare.com/pages/functions/bindings/#secrets).

검증: `node --test tests/*.test.mjs`. 실결제를 하지 않고 API 요청·통보 위조 방지·중복 처리·롤백·환불·입금 대기를 검증합니다.

### 요금 바꾸기 — `assets/js/data/pricing-gundae.js` (1호 · 요금표 v2.1) · `pricing-gundae2.js` (2호 · 요금표 v1.1)
요금표의 숫자는 공간마다 이 파일 한 곳에만 있습니다(2호는 같은 구조에 `surcharge`·`opening`·공간 표시 항목이 더 있습니다). 숫자를 고치면 상세 페이지와 요금 안내 페이지의 요금표·패키지·성수기 요금표·요금 달력·옵션·환불표, 예상 금액 계산기, 견적서, 관리자 견적, 목적별 요금 예시, 공간 카드의 '시간당 4만 원부터'가 함께 바뀝니다.
- 시간당 요금: `hourly` — 요일 구분(`wd` 월–목 / `fri` 금 / `sat` 토 / `sun` 일) × 시간대(`morning` 07–12시 / `day` 12–17시 / `evening` 17–24시 / `night` 24–07시). 예: 토요일 저녁을 22만 원으로 → `sat: { … evening: 220000 … }`
- 패키지: `packages` — `price`(할인가)와 `regular`(정상가). 정상가는 시간당 요금을 더한 값과 같아야 하며, `tools/test_pricing.js`가 이를 확인합니다.
- 인원: `people` — 기준 인원 20명, 1명당 추가 1만 원, 최대 200명.
- **이용 시간**: `openFrom: 5`(새벽 05시부터) · `openTo: 31`(다음 날 07시까지). 새벽 05–07시는 `dawn`에 적힌 대로 심야(`night`) 시간대 요금으로 계산합니다(다르게 받으려면 `dawn.band`를 `morning`으로). `breakfastUntil: 9` — 이 시각 전에 시작하면 계산기에 '조찬 모임은 따로 연락 주시면 추가 협찬·할인 안내' 문구가 붙습니다.
- **성수기** `peak` (요금편성표 2026-10-17): `periods`(10/30·31, 12월, 1월) · `dates`(특정일 → 적용 구분: 10/30, 10/31, 12/24, 12/25, 12/31, 1/1) · `months`(해당 월의 실제 요일 → 적용 구분) · `types`(적용 구분 14종 — 포함 인원 `people`, 시간제 1건당 가산액 `surcharge`, 시간당 `hourly`, 패키지 `pkg`). 성수기에는 공휴일 규칙 대신 실제 요일을 쓰고, 자정을 넘어도 시작한 이용일 요금입니다. 포함 인원이 50명인 날은 50명까지 추가 요금이 없고(적게 와도 같은 금액), 시간제에만 가산액이 한 번 더해지며 패키지에는 이미 들어 있습니다. 다음 해 성수기를 정하면 `periods`·`dates`·`months`에 날짜를 추가하고 `types`에 금액을 넣으면 됩니다. 성수기 날짜는 온라인 이용권(`/products/`)으로 결제할 수 없고(서버가 PEAK 오류로 막고 예약 신청으로 안내), 예약 신청 · 금액 확인에서 그날 금액으로 신청받습니다.
- **별도 안내** `special`·`specialNote`: 조찬 모임·정기 모임·제휴 모임·팝업 카드와 '따로 연락 주시면 추가 협찬과 할인을 안내' 문구. 요금 안내·건대 상세·계산기 결과·견적서·홈·이용 안내·문의 페이지에 같이 나옵니다.
- 옵션: `options`(금액이 있는 것), `askOptions`(상담 시 안내), `included`(무료 기본 제공).
- 보증금 `deposit`, 법인 결제 안내 `corporate`, 별도 안내 `special`, 환불 `refund`.
- 요금을 바꿀 때는 맨 위 `version`과 `effectiveFrom`도 함께 고쳐 주세요. 계산기와 견적서에 표시되는 요금표 버전입니다.

### 예약 신청 · 금액 확인 (`/inquiry/`, 건대 상세 #estimate, 요금 안내 #estimate)
계산기와 예약 신청이 한 화면에 있습니다. 성수기 날짜를 고르면 날짜 옆에 '성수기 · 12월 토요일 기준 · 50명 포함' 표시가 붙고 그날 요금·포함 인원으로 계산되며, 성수기에는 접수 화면의 '바로 결제하기' 링크가 나오지 않습니다. 순서는 **① 이용 시간**(시작·종료 선택, 그 아래 ‘패키지도 가능합니다.’와 낮·올데이·올나잇 패키지 버튼 — 누르면 시간이 자동으로 들어가고 그날 요금이 버튼에 표시) → **② 이용일**(공휴일 자동 반영) → **③ 인원** → (접힌) **옵션·모임 유형·정기 이용(선택)** 입니다. 오른쪽(모바일은 아래) 카드에 예상 금액이 바로 나옵니다.

- 선택한 시간이 패키지와 같고 결제 서버가 켜져 있으면 접수 화면에 **바로 결제하기** 링크가 나옵니다. `/order/`로 이어지며 접수번호가 자동으로 연결되어, 결제가 끝나면 이 신청이 ‘예약 확정’으로 바뀌고 예약이 자동 등록됩니다.

- **메뉴**: 머리말은 `건대 1호 · 건대 2호 · 공간 찾기▾ · 모임 모집▾ · 출장뷔페 · 이용권 구매 · 이용 안내▾ · 호스트·광고▾`. ▾ 메뉴는 마우스를 올리거나 Tab 으로 열리고, 모바일 메뉴는 공간·예약·모임·안내·호스트 다섯 묶음입니다. 메뉴 내용은 `tools/build_site.py`의 `HEADER`에서 바꿉니다.

  - 주최자 관리 링크는 서버 비밀값(`CONFIRM_SECRET`, 없으면 `ADMIN_KEY`)으로 모임번호를 서명해 만들기 때문에 **비밀값을 바꾸면 기존 관리 링크가 모두 바뀝니다.** 주최자가 링크를 잃어버리면 관리자 화면 모임 상세의 `주최자 관리 링크 복사`로 본인 확인 뒤 다시 보내 주세요.

  - 공개 화면에는 주최자 연락처·예약번호·운영 메모가 나가지 않습니다(`_platform.js`의 `publicMeetup`). 참가비는 메가스팟이 받지 않고 주최자가 안내합니다.
- **호스트 입점** (`/host/`): 공간 등록 신청(A) · 입점 상담(B) · 운영 위탁 상담(C) · 배너 광고·제휴(D) 네 갈래. `/host/register/`는 6단계 신청서이고 작성 중인 내용(연락처·동의 제외)은 이 브라우저에 30일 임시 저장됩니다. 들어온 신청은 관리자 **입점·광고 신청**에서 종류·상태로 걸러 보고, 상태(접수→검토 중→보완 요청→진행 확정/보류/반려·종료)와 운영 메모를 남깁니다.
- **등록 공간** (`/spaces/listing/?id=L-…`): 공간 등록 신청 상세의 `이 내용으로 등록 공간 초안 만들기` 또는 관리자 **등록 공간 → + 새 공간**으로 만들고, 사진 주소·요금 안내·호스트 사업자 정보를 다듬은 뒤 **공개**로 바꾸면 공간 찾기 목록(외부 호스트·문의형 표시)과 상세 페이지에 나옵니다. 상세의 문의는 '문의 관리'에 **맞춤 요청**으로 들어오고 문의 원문 맨 위에 `[등록 공간 문의] 공간 이름`이 붙습니다. 사진은 사용 허락을 받은 것만 올려 주세요.
- **배너 광고**: 광고 자리는 `home-mid`(홈 중간) · `list-top`(공간 찾기·모임 목록 위) · `list-card`(목록 사이 카드) · `content-bottom`(이용 안내·목적별 안내·모임 상세·등록 공간 상세 아래) 네 곳입니다. 관리자 **배너 광고**에서 자리·제목·보조 문구·버튼 문구·연결 주소(https:// 또는 /경로)·이미지·색·기간·우선순위를 정하고 켜면 1분 안에 반영됩니다. 유료 광고는 화면에 `광고 · 광고주`가 자동으로 붙고, 게재 중인 광고가 없는 자리는 `assets/js/site.js`의 `HOUSE_ADS`(건대 1호·2호·모임 등록·공간 등록 안내)가 대신 보입니다. 노출 수·클릭 수·클릭률은 관리자 목록에서 봅니다.

## 7. 기술 메모

- 빌드 도구·프레임워크 없이 순수 HTML/CSS/JS 로 되어 있어 GitHub 웹에서 파일을 직접 고칠 수 있습니다.
- 서체: Pretendard(jsDelivr CDN), Anton·Black Han Sans(Google Fonts). 오프라인에서는 기본 고딕으로 표시됩니다.
- 3D 뷰어는 three.js(MIT, `THREE-LICENSE.txt`)를 포함한 단일 파일이며, 실측 도면과 공간 사진으로 재구성한 모델입니다(실제 스캔 아님).
- API 가 없거나 DB 가 연결되지 않으면 모든 폼은 자동으로 체험 모드로 바뀌어 사이트가 깨지지 않습니다.
- 관리자 API는 `ADMIN_KEY`로 로그인해 받은 쿠키(HttpOnly·Secure·SameSite=Strict, `/api/` 경로 전용)로 보호되며, 15분 안에 8번 틀리면 15분간 로그인을 막습니다. 키는 Cloudflare Secret에만 저장됩니다. 관리자 페이지는 검색 엔진에 노출되지 않습니다(`noindex`, robots Disallow).
- 자동 입력(스팸) 방지: 예약 신청·문의(`/api/inquiry`)는 같은 IP에서 10분에 8건, 입점 문의는 5건, 후기 작성은 10번까지만 받고 그 뒤에는 잠시 막습니다(429). 신청 폼에는 사람 눈에 보이지 않는 칸(허니팟)이 있어 봇이 채우면 저장하지 않습니다. 고객에게 보이는 오류 문구에는 서버 내부 메시지를 넣지 않습니다.
- 온라인 결제 보호: 운영자가 **임시 확보**로 잡아 둔 날짜는 온라인 결제가 막히고 상담으로 안내합니다(이중 예약 방지). 주문에 접수번호를 적어도 **같은 휴대폰 뒷 4자리**로 들어온 신청일 때만 연결되어, 다른 사람의 신청을 결제로 바꿀 수 없습니다. 결제창이 열린 동안에는 결제하기 버튼이 잠겨 같은 주문이 두 번 만들어지지 않습니다.
- 고객 달력(`/api/availability`)은 운영자가 표시한 마감·임시 확보 날짜를 보여 주고, **확정 예약이 있는 날은 ‘일부 시간 예약 (다른 시간 가능)’**으로 보여 줍니다(2026-10-17부터, 고객은 그 날짜를 골라 다른 시간대로 신청 가능). 하루 전체를 닫으려면 관리자 일정 달력에서 ‘마감’으로 표시합니다.
- 유입 경로: 방문자가 바깥 사이트(네이버·구글·인스타그램 등)나 utm 값이 붙은 링크로 들어오면 그 사이트 주소와 utm 값을 **방문자 브라우저에만** 30일 보관했다가, 예약 신청·문의를 보낼 때 함께 보냅니다. 서버는 사이트 이름(호스트)과 utm 값만 저장하고 검색어가 담긴 전체 주소는 저장하지 않습니다. 광고·SNS 링크에는 `?utm_source=instagram&utm_campaign=12월이벤트`처럼 붙이면 관리자 화면에서 구분됩니다.
- 관리자 채널 바로가기 주소는 `assets/js/pages/admin.js` 맨 위 `CHANNEL_LINKS`에서 바꿉니다.
