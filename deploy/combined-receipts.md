# 이용료 + 반환 보증금 합산 입금 · 2026-11-05

관리자 ‘수납·환불 기록’에서 기록 종류를 ‘이용료 + 보증금 합산 입금’으로 고릅니다. 남은 이용료와 예약에 설정된 보증금을 더한 총액을 기본으로 표시하며 실제 입금액을 수정할 수 있습니다. 이용료·보증금 구분을 확인하고 한 번 저장합니다.

- 이용료만 기존 수납 장부에 합산합니다. 보증금은 별도 입금 확인과 `booking_refunds.amount`에 보존합니다. 부분 이용료 입금도 지원하며 이용료 잔금 초과, 보증금 변경, 이미 확인한 보증금, 취소 예약, 동일 문의의 복수 예약은 거절합니다.
- 수납·합산 입금 원본·보증금 확인·문의 메모·예약확정서 발급·환급 계좌 알림 outbox를 D1의 한 트랜잭션으로 저장합니다. 기존 체크리스트·메모를 보존합니다. 미발송 보증금 입금 요청은 중지하고, 등록된 환급 계좌에는 재요청하지 않습니다.
- 동일 요청을 복구하거나 동시에 저장해도 수납·메모·계좌 알림을 중복 생성하지 않습니다. 기존 브라우저 저장 복구 기능을 그대로 사용합니다. 중간 저장 오류는 전체 롤백합니다.
- 계좌 요청은 기존 승인·시험 수신을 마친 자동 발송 설정과 09:00–21:00 발송 시간을 따릅니다. 설정 OFF라면 수납은 저장하고 별도 안내가 필요함을 보여줍니다. 실제 송금·환급을 실행하는 기능은 아닙니다.
- 합산 입금 저장 시 확정서를 최신 이용료 수납액·잔금·보증금·식음료 구성으로 자동 재발급합니다. 기존 행사명·안내 메모·금액 공개 여부·포함 항목·환불 조건·최초 발급일을 보존하고 발급 버전을 한 번 올립니다. 이전 확정서가 없으면 최초 발급합니다. 기존 고객용 링크는 유지합니다. 일반 수납·환불의 수동 확정서 절차는 그대로입니다.
- 원본은 `booking_combined_receipts`와 `booking_payment_entries`에 남습니다. 이용료 기록의 정정·취소는 기존 사유·이력 기능을 사용하며 보증금 확인·실제 환급은 별도로 관리합니다.

마이그레이션: `migrations/20261105_combined_receipts.sql`. `schema.sql`과 자동 초기화용 `functions/api/_schema.js`에 포함하여 기존 운영 DB에도 적용합니다. 기존 예약 소급 처리·고객 재발송·운영 자동 발송 설정 변경은 하지 않습니다.

검증: 메모리 SQLite의 합산 입금, 동시 저장, 응답 유실 복구, 중간 오류 롤백, 금액·예약 변경, 계좌 기등록, 문의 없는 예약, 확정서 재발급, 기존 DB 초기화 검증. 실제 고객 수납·외부 메시지 발송은 검증에 사용하지 않습니다.

## 합산 입금과 확정서 자동 발급

- 저장 직전에 최신 예약·식음료·기존 문서를 읽고, 합산 입금으로 늘어날 이용료 수납액과 정산 버전을 반영한 확정서를 준비합니다. 보증금은 이용료에서 계속 제외합니다.
- 재발급한 확정서와 감사 이력은 수납·보증금·알림 outbox와 같은 DB 트랜잭션에 저장합니다. 문서 저장 오류 시 전체 롤백합니다. 요청 ID 재시도·동시 클릭은 문서를 중복 발급하지 않습니다.
- 문서를 준비한 뒤 다른 관리자가 확정서·예약·고객·인원·식음료·비공개 설정을 바꾸면 저장 조건을 다시 확인하여 덮어쓰지 않습니다.
- 계좌 요청 생성 전에 확정서를 갱신하므로 문서 변경이 새 계좌 안내를 재검토 상태로 막지 않습니다. 고객용 문서에서 표시하는 수납·잔금과 저장된 최신 정산 버전이 같습니다.
- 최초 발급·기존 문구/금액 비공개 보존·부분 수납·식음료 포함·기존 링크·재시도·중간 오류 롤백·동시 문서 변경을 가상 DB로 검증합니다. 운영 고객의 수납이나 문서·발송은 개발 검증에 사용하지 않습니다.

## 모바일 처리·완료 화면 · 2026-11-05

- 긴 설명과 기존 결제 방식별 합계는 접힌 내역/안내로 옮겼습니다. 현재 잔금·보증금 요약과 입력을 먼저 표시합니다. 390px에서 입력 폼 시작 위치가 약 958px에서 261px로 줄었습니다.
- 저장 후 입력 폼 대신 완료 카드를 표시하고 자동으로 결과에 초점을 옮깁니다. 이용료·보증금, 확정서 자동 발급 여부, 계좌 안내의 대기/접수/성공/실패를 구분합니다. 최신 확정서 열기·알림톡 상태 새로고침·이력 보기로 연결합니다. 상태 새로고침은 새 알림톡을 발송하지 않습니다.
- 금액 입력은 숫자 키보드를 요청하고, 확인 체크와 주요 버튼은 44px 이상 터치 영역을 확보합니다. 오류가 발생하면 메시지가 보이도록 이동합니다. 저장 중에는 화면 이동을 잠그고, 보증금/수납 변경 충돌 시 최신 정보를 다시 읽습니다.
- `node tests/helpers/combined-receipts-preview.mjs`는 127.0.0.1의 로컬 검증 서버입니다. 실제 API 핸들러·메모리 SQLite·운영 CSS/JS·고객 확정서 페이지를 사용하고 모든 외부 제공자 호출은 가상 응답으로 대체합니다. 실제 인증정보·고객 DB·외부 발송에는 연결하지 않습니다.
- Chrome 320×740·390×844에서 입력→합산 입금 저장→확정서 자동 재발급→고객용 확정서 조회→가상 알림톡 처리→완료 카드의 수신 성공 갱신을 확인했습니다. 수납 2,400,000원·잔금 0원·보증금 확인·발급 버전 2·재발급 불필요·계좌 요청 가상 1건을 대조했습니다. 두 화면 모두 가로 넘침이 없었습니다.
