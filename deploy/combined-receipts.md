# 이용료 + 반환 보증금 합산 입금 · 2026-11-05

관리자 ‘수납·환불 기록’에서 기록 종류를 ‘이용료 + 보증금 합산 입금’으로 고릅니다. 남은 이용료와 예약에 설정된 보증금을 더한 총액을 기본으로 표시하며 실제 입금액을 수정할 수 있습니다. 이용료·보증금 구분을 확인하고 한 번 저장합니다.

- 이용료만 기존 수납 장부에 합산합니다. 보증금은 별도 입금 확인과 `booking_refunds.amount`에 보존합니다. 부분 이용료 입금도 지원하며 이용료 잔금 초과, 보증금 변경, 이미 확인한 보증금, 취소 예약, 동일 문의의 복수 예약은 거절합니다.
- 수납·합산 입금 원본·보증금 확인·문의 메모·환급 계좌 알림 outbox를 D1의 한 트랜잭션으로 저장합니다. 기존 체크리스트·메모를 보존합니다. 미발송 보증금 입금 요청은 중지하고, 등록된 환급 계좌에는 재요청하지 않습니다.
- 동일 요청을 복구하거나 동시에 저장해도 수납·메모·계좌 알림을 중복 생성하지 않습니다. 기존 브라우저 저장 복구 기능을 그대로 사용합니다. 중간 저장 오류는 전체 롤백합니다.
- 계좌 요청은 기존 승인·시험 수신을 마친 자동 발송 설정과 09:00–21:00 발송 시간을 따릅니다. 설정 OFF라면 수납은 저장하고 별도 안내가 필요함을 보여줍니다. 실제 송금·환급을 실행하는 기능은 아닙니다.
- 변경된 수납으로 확정서를 다시 발급하도록 안내합니다. 환급 금액이 같은 확정서 재발급은 계좌 요청 outbox를 재검토 상태로 바꾸지 않습니다. 실제 예약자·시간·환급 금액 변경은 기존 검토 절차를 유지합니다.
- 원본은 `booking_combined_receipts`와 `booking_payment_entries`에 남습니다. 이용료 기록의 정정·취소는 기존 사유·이력 기능을 사용하며 보증금 확인·실제 환급은 별도로 관리합니다.

마이그레이션: `migrations/20261105_combined_receipts.sql`. `schema.sql`과 자동 초기화용 `functions/api/_schema.js`에 포함하여 기존 운영 DB에도 적용합니다. 기존 예약 소급 처리·고객 재발송·운영 자동 발송 설정 변경은 하지 않습니다.

검증: 메모리 SQLite의 합산 입금, 동시 저장, 응답 유실 복구, 중간 오류 롤백, 금액·예약 변경, 계좌 기등록, 문의 없는 예약, 확정서 재발급, 기존 DB 초기화 검증. 실제 고객 수납·외부 메시지 발송은 검증에 사용하지 않습니다.
