# 예약 확정·변경 안내 연결 개선 · 2026-11-03

이번 작업은 로컬 코드와 가상 예약으로 검증했습니다. 운영 배포·실제 고객/운영자 발송·자동 발송 설정 변경·기존 고객 일괄 발송은 수행하지 않았습니다.

## 예약 확정

- 관리자 직접 등록, 문의에서 확정, 재확정, 온라인 이용권 결제의 예약 생성/상태 변경을 같은 DB 트리거로 기록합니다.
- 기존 고객 발송·자동 발송 설정이 모두 켜진 이후의 새 확정만 `booking_guide_events`에 기록합니다. 예약과 이벤트는 같은 트랜잭션에 포함됩니다.
- Pages의 `waitUntil`로 외부 발송 처리를 넘겨 예약 확정·결제 통보 응답을 지연하지 않습니다. 기록 저장 전 장애는 대기 이벤트를 보존합니다.
- API 요청 후 백그라운드 처리 및 기존 HMAC 인증 보증금 정기 처리의 `tick` 경로에서 시설 안내 대기·도착 결과를 확인합니다. 별도 타이머 설치나 실행은 이번 작업에서 하지 않았습니다. 인증 없는 호출과 읽기 전용 `status` 경로는 발송을 실행하지 않습니다.
- 발송 중지·설정 변경 시 기존 자동 대기는 취소하며, 다시 켜도 소급 생성하지 않습니다. 설치 시점의 기존 예약에는 기준 상태만 만들고 확정 이벤트는 생성하지 않습니다.

## 변경 후 재안내

- 예약자·연락처·호점·날짜·이용 시간이 바뀌면 예약별 안내 버전을 올립니다. 내부 메모·금액만 수정하면 시설 안내 버전은 바뀌지 않습니다.
- 관리자 **이용 안내 알림톡 → 변경 후 재안내 필요**에서 최신 수신번호·문구를 미리보고 수동 발송합니다. 기존 승인 템플릿을 그대로 사용하며, 고객에게 전달되는 문구는 최신 예약 내용입니다. 별도의 변경 전/후 비교 알림톡 템플릿은 등록하지 않았습니다.
- 변경 전 미리보기와 아직 접수하지 않은 큐는 무효화합니다. 이전 발송의 접수·전송 중·결과 불명은 버전이 달라도 중복 잠금을 유지합니다. 이전 버전의 늦은 수신 성공은 새 버전을 완료 처리하지 않습니다.
- 보증금 입금/계좌 요청이 미발송 대기 중 바뀌면 **예약 변경 · 재안내 확인 필요**로 남깁니다. 관리자에 표시된 최신 수신번호·문구와 사유를 확인해야 새 이력을 만들 수 있습니다. 확인 후 예약/설정이 바뀌면 이전 확인값을 거부합니다. 원래 미발송 이력은 보존합니다.
- 이미 접수됐거나 결과가 불명확한 보증금 안내는 이 검토 기능으로 재발송하지 않습니다. 입금·계좌 등록이 끝났거나 취소·종료 등으로 불필요해진 안내도 다시 준비하지 않습니다.

## 같은 문의에 예약이 여러 개 있는 경우

- 안내 완료·수동 확인은 `booking_guide_state`의 예약번호와 버전에 귀속됩니다. 신규로 추가한 다른 예약은 이전 문의의 완료 체크를 상속하지 않습니다.
- 첫 예약을 만들기 전 수동 안내한 기록과 기존 예약의 과거 체크는 보존합니다. 과거 문의 체크의 대상 예약이 불명확한 경우 보수적으로 기존 수동 안내 기록을 유지합니다.
- 문의 상세의 현장 안내 체크는 취소되지 않은 연결 예약 전체의 현재 안내 상태를 표시합니다. 복수 예약에서 수동 체크하면 **연결된 예약 전체 현장 안내 확인**임을 표시합니다. 다른 체크를 저장하는 동작으로 새 예약의 안내를 완료 처리하지 않습니다.
