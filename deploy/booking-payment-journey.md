# 예약 확정·분할 납부 알림 운영

- 확정 상태로 생성하거나 확정으로 변경하면 예약금·전액 납부 여부와 무관하게 승인된 UN_2935로 전용 통합 링크를 보냅니다. 기존 예약 확정 알림은 소급 생성하지 않습니다.
- 확정 직후 시설 안내 자동 발송은 중지하며, 이용 전날 09–21시 방문 안내를 보냅니다. 관리자의 시설 안내 수동 발송은 유지합니다.
- 통합 페이지는 실제 이용료 장부(온라인 및 계좌 입금·환불)를 기준으로 총 이용료·순수납·잔금을 표시합니다. 반환 보증금은 별도이며 합산 입금은 기존 합산 입금 메뉴로 분리 기록해야 합니다.
- 확정 알림 준비 시 확정서가 없는 신규 예약은 최신 장부·견적 기준으로 자동 발급합니다. 기존 발급 문서를 임의로 덮어쓰지 않습니다.
- 잔금 기한은 기본 이용 3일 전(임박 예약은 확정일), 관리자 수납·정산의 ‘잔금 납부일’에서 수정합니다. 납부 기한 전날 안내하고 당일까지 처리 지연을 보완합니다. 확정 당일 잔금 독촉은 하지 않습니다.
- 전액 납부를 처음 확인하면 이용료 완납 알림을 1회 생성합니다. 처음부터 전액 납부한 예약은 확정 알림만 보냅니다. 보증금 입금 여부는 별도 확인합니다.
- UN_6619 잔금 안내, UN_6620 이용료 납부 완료, UN_6621 방문 전날 안내: 2026-11-12 검수 요청. 승인 전 발송 보류, 승인 후 본문·버튼 일치 확인 시 자동 활성화합니다. 날짜가 지난 안내는 취소합니다.
- 모든 고객 발송은 알림톡 우선, 알리고 failover Y 대체 문자입니다. 모호한 발송 결과는 중복 발송하지 않습니다. 관리자 ‘거래 알림 이력’에 발송 및 대체 문자 결과를 남깁니다.
- 기존 서명된 보증금 타이머가 새 플래너와 거래 알림 큐를 순서대로 실행합니다. API 상태 조회는 발송하지 않습니다.
- 최초 활성화는 기존 HMAC 인증을 사용하는 POST /api/deposit-notifications/journey-setup 에 action=enable_booking_journey 를 포함한 서명된 JSON으로 실행합니다. 암호화 키와 승인된 확정 템플릿을 검사하고 설정을 저장합니다.
- 설정 booking_journey.enabled=false로 새 자동 발송을 중지할 수 있습니다. 기존 전송 요청 결과의 조회는 계속됩니다.

검증: booking-journey.test.mjs의 가상 예약·수납·승인/미승인·개별 수신자·예약 변경·정보 비공개 테스트. 실제 고객에게 시험 메시지는 보내지 않았습니다.

## 운영자 실제 수신 시험

서명된 POST /api/deposit-notifications/journey-trial 에 action=send_booking_deposit_test, test_id(UUID), receiver(등록 운영자 번호), confirm_test=true를 보냅니다. 최초 1건만 실제 발송하고 같은 test_id는 중복 발송 없이 상태를 반환합니다. 시험 예약은 booking_journey_trials에 별도 저장하며, 실제 bookings/orders/수납 장부/달력은 변경하지 않습니다. 링크는 24시간 후 만료되며 계좌 등록·실제 입금 기능을 제공하지 않습니다. 관리자 거래 알림 이력에서 TEST 번호로 실제 알림톡 수신 결과를 확인합니다.

전액 첫 입금은 예약 확정 알림의 수신 이후 반영돼도 완납 알림을 추가하지 않습니다. 부분 납부를 확인했거나 분할 수납 내역이 있는 경우에만 잔금 완납 안내를 생성합니다.

## 발송 시점별 버튼 · 2026-11-12 변경

- 예약 확정: UN_6623 검수 요청. ‘예약 안내 확인’은 고객 전용 통합 링크, ‘뷔페·케이터링·칵테일 안내’는 /catering/#food-compare입니다. 승인 전에는 기존 승인 UN_2935로 확정 안내를 유지하며 승인 후 새 2버튼으로 자동 전환합니다.
- 방문 전날 자동 이용 안내: UN_6624 검수 요청. ‘입실 및 이용 안내’는 시설 안내 페이지, ‘주차권 구매’는 주차권 구매 페이지입니다. 식음료 버튼은 포함하지 않습니다. 기존 검수 중 UN_6621 대신 새 버전을 연결합니다.
- URL 치환은 전용 통합 링크 버튼에만 적용합니다. 식음료·시설·주차권의 고정 URL을 예약 링크로 바꾸지 않습니다. 대체 문자에도 해당 발송 단계의 버튼 URL을 모두 포함합니다.

## 입금 기록 시 확정서 자동 갱신

- 확정·이용 완료 예약에서 이용료 수납을 저장하면 최신 장부 기준의 확정서를 같은 트랜잭션에서 발급·갱신합니다. 예약금·잔금 구분 없이 실제 받은 추가 금액을 기록합니다.
- 수납 정정·기록 취소·복원·수기 환불도 최신 내역으로 갱신합니다. 실제 예약 취소 상태에서는 활성 예약확정서를 만들지 않습니다.
- 기존 최초 발급일, 고객·행사명·특약·이용 조건·환불 조건·반환 보증금·금액 공개 설정을 보존하고 갱신 일시와 발급 버전을 갱신합니다. 확정서가 없으면 견적·예약의 최신 조건으로 발급합니다.
- 기존 통합 링크는 그대로 사용하며, 고객이 열거나 새로고침하면 최신 문서와 납부액·잔금을 함께 확인합니다.
- 저장 실패 시 수납과 문서가 함께 롤백됩니다. 재시도는 수납·발급·이력을 중복 생성하지 않습니다. 다른 관리자가 문서·견적·보증금·공개 설정을 바꾸면 충돌을 알리고 최신 내용을 확인하게 합니다.
- 총 이용료가 미정이거나 예약 확정 전인 경우에는 수납만 보존하고 예약확정서 자동 발급은 보류합니다. 온라인 PG 통보에 의한 문서 무효화는 기존 처리 범위입니다.

## 보증금 입금 안내 시점 · 2026-11-13

통합 예약 안내 활성화 시 예약 확정 직후에는 통합 링크 1건을 안내합니다. 보증금 미납 안내는 기존 outbox에 대기하며, 보증금 납부 기한 전날 한국시간 09시부터 미납 확정 예약만 발송합니다. 보증금 기한은 이용 3일 전(임박 예약은 확정일)이며 통합 페이지와 안내 문구가 같은 기한을 사용합니다. 확정 당일에는 별도 보증금 안내를 보내지 않습니다. 서버 복구 시 납부 기한 당일까지 미발송 건을 보완하며, 기한이 지난 건은 취소합니다.

한 달 이후의 예약도 발송 대기가 기존 7일 유효기간 때문에 사라지지 않습니다. 미래 대기는 계좌 요청·환급 완료 메시지의 처리를 막지 않습니다. 입금 확인·예약 취소는 발송 직전에 다시 검사하며 기존 접수·수신 성공·결과 불명 메시지를 재발송하지 않습니다.

이미 보증금을 받은 상태로 신규 확정하는 경우에도 예약 생성 트리거에서 계좌 요청을 추가하지 않습니다. 계좌 등록은 통합 링크에서 가능하며, 확정 후 실제 보증금 입금 확인에 따른 계좌 안내와 이용 후 환급 알림은 기존 흐름을 유지합니다.

서명된 /api/deposit-notifications/status 의 payment_schedule=day_before_due로 운영 적용을 조회할 수 있습니다. 새 템플릿 승인이나 별도 발송 서버 설정 변경은 필요하지 않습니다.

## 승인 완료 후 전체 흐름 점검 · 2026-11-13

- 고객 알림은 승인된 현행 템플릿을 사용합니다. UN_2935 한 버튼 확정 안내로의 임시 폴백은 종료했습니다. 1호 입실 전 안내는 UN_6624(시설·주차 2버튼), 2호는 1호 출입정보 전달을 막기 위해 승인된 UN_6621 예약별 통합 링크를 사용합니다. 2호 전용 입실·장비 안내는 별도 제작이 필요합니다.
- 예약 전날·당일 확정은 확정 통합 안내가 입실 안내를 대신합니다. 확정과 동시에 보증금 입금을 확인한 경우에도 계좌 요청을 통합 안내와 중복 발송하지 않습니다. 실제로 나중에 보증금을 확인하는 흐름과 수동 계좌 재요청은 유지합니다.
- 수동 이용 안내도 UN_6624로 전환합니다. 예전 자동·세 버튼 수동 안내의 재활성화를 차단하고, 자동·수동 입실 안내가 수신자별로 서로 중복 발송을 막습니다. 일정 변경 후에는 최신 조건으로 수동 재안내가 가능합니다.
- 최초 발송 잠금에 예약 조건 스냅샷을 기록하고, 승인 조회 중 일정이 바뀌면 이전 내용으로 보내지 않습니다. 예전 시간 구간(pkg-day 등)으로 저장된 예약은 기존 시간표를 해석합니다.
- 자동 입실 안내 결과도 예약 관리의 안내 현황에 반영합니다. 설정 전환 전 접수된 메시지는 당시 설정 해시를 보존해 결과 조회만 이어가며 다시 발송하지 않습니다.
- 서명된 journey-operations는 audit(개인정보 없는 큐·설정 요약), audit_extended(보증금·주차 승인과 준비 상태 추가 확인), test_current_arrival(등록 운영자 번호로 1회 시험), check_current_arrival(시험 결과 확인), activate_approved_notifications(승인 캐시 준비·현행 수동 템플릿 설정·이전 미발송 큐 정리)만 지원합니다. 실제 고객 예약·결제·장부는 변경하지 않습니다.

### 예약별 알림 관리 · 2026-11-13

- 관리자 `#guide-messages`는 예약자별 알림 관리 화면입니다. 이전 입실 안내 상세·설정은 `#guide-delivery`, 기존 설정 별칭 `#guide-settings`에서 유지합니다.
- 예약 현황·목록의 ‘알림 현황’에서 해당 예약으로 바로 이동합니다. 검색·호점·미래/과거/전체 기간과 페이지 이동을 지원합니다.
- 통합 확정, 잔금, 잔금 납부 완료, 입실·주차, 보증금 입금, 환급 계좌 등록, 보증금 환급 완료의 상태를 번호별로 구분합니다. 문의·관리자 문자·취소·환불·연결 주차 이력도 함께 표시합니다.
- 수동 발송은 미발송 번호만 미리보기 후 요청합니다. 만료/사용한 미리보기, 연락처·납부·발송 이력 변경, 수신 성공, 접수/불명확 상태는 차단합니다. 기존 취소·환불 등 이벤트는 명확히 실패한 고객 이력만 재시도하며 금융 처리를 새로 만들지 않습니다.
- 예약 확정 외의 주요 안내는 기존 09~21시·미납·기한·전날 조건을 유지합니다. 첫 전액 납부의 별도 납부 완료 안내는 제공하지 않습니다. 발송 요청 후 기존 자동 작업이 접수·배송 결과를 기록하며 조회/미리보기만으로 메시지는 보내지 않습니다.

### 예약 달력과 알림 원문 보기 · 2026-11-13

- 예약별 알림의 목록은 월간 이용일 달력으로 표시합니다. 월 이동·이번 달·예약자/번호/연락처 검색·호점 필터를 제공하며 20건 페이지 제한을 달력에 적용하지 않습니다. 한 달 최대 500건이며 초과 여부를 표시합니다.
- 안내 제목과 개별 발송 이력을 누르면 번호별 상태·시각·당시 본문·버튼을 조회합니다. 기존 기록은 공급사 이력 또는 기존 스냅샷에서 조회하며, 원문이 없으면 현재 예시를 실제 수신 내용으로 표시하지 않습니다.
- 앞으로 발송하는 거래/보증금/기존 안내/주차 알림은 실제 전송 직전 본문·버튼·대체 문자 내용을 `settings`의 `notification_content:<engine>:<id>`에 AES-GCM으로 암호화해 저장합니다. 전용 링크 원문을 평문 장부나 이벤트 로그에 보관하지 않습니다. 암호화 키가 없는 기존 구성은 원문 저장을 건너뛰고 기존 발송 동작을 유지합니다.
- 내용 조회는 예약에 실제 연결된 이력만 허용하고, 메시지 발송·확정서 생성·링크 재발급을 하지 않습니다. 미발송 안내는 현재 예약 기준 예시임을 별도로 표시합니다.
