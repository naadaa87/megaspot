# 예약 확정·분할 납부 알림 운영

- 확정 상태로 생성하거나 확정으로 변경하면 예약금·전액 납부 여부와 무관하게 승인된 UN_2935로 전용 통합 링크를 보냅니다. 기존 예약 확정 알림은 소급 생성하지 않습니다.
- 확정 직후 시설 안내 자동 발송은 중지하며, 이용 전날 09–21시 방문 안내를 보냅니다. 관리자의 시설 안내 수동 발송은 유지합니다.
- 통합 페이지는 실제 이용료 장부(온라인 및 계좌 입금·환불)를 기준으로 총 이용료·순수납·잔금을 표시합니다. 반환 보증금은 별도이며 합산 입금은 기존 합산 입금 메뉴로 분리 기록해야 합니다.
- 확정 알림 준비 시 확정서가 없는 신규 예약은 최신 장부·견적 기준으로 자동 발급합니다. 기존 발급 문서를 임의로 덮어쓰지 않습니다.
- 잔금 기한은 기본 이용 3일 전(임박 예약은 확정일), 관리자 수납·정산의 ‘잔금 납부일’에서 수정합니다. 납부 기한 전날 안내하고 당일까지 처리 지연을 보완합니다. 확정 당일 잔금 독촉은 하지 않습니다.
- 전액 납부를 처음 확인하면 이용료 완납 알림을 1회 생성합니다. 처음부터 전액 납부한 예약은 확정 알림만 보냅니다. 보증금 입금 여부는 별도 확인합니다.
- UN_6619 잔금 안내, UN_6620 이용료 납부 완료, UN_6621 방문 전날 안내: 2026-11-12 검수 요청. 승인 전 발송 보류, 승인 후 본문·버튼 일치 확인 시 자동 활성화합니다. 날짜가 지난 안내는 취소합니다.
- 모든 고객 발송은 알림톡 우선, 알리고 failover Y 대체 문자입니다. 모호한 발송 결과는 중복 발송하지 않습니다. 관리자 ‘거래 알림 이력’에 발송 및 대체 문자 결과를 남깁니다.
- 기존 서명된 보증금 타이머가 새 플래너와 거래 알림 큐를 순서대로 실행합니다. API 상태 조회는 발송하지 않습니다.
- 최초 활성화는 기존 HMAC 인증을 사용하는 POST /api/deposit-notifications/journey-setup 에 action=enable_booking_journey 를 포함한 서명된 JSON으로 실행합니다. 암호화 키와 승인된 확정 템플릿을 검사하고 설정을 저장합니다.
- 설정 booking_journey.enabled=false로 새 자동 발송을 중지할 수 있습니다. 기존 전송 요청 결과의 조회는 계속됩니다.

검증: booking-journey.test.mjs의 가상 예약·수납·승인/미승인·개별 수신자·예약 변경·정보 비공개 테스트. 실제 고객에게 시험 메시지는 보내지 않았습니다.

## 운영자 실제 수신 시험

서명된 POST /api/deposit-notifications/journey-trial 에 action=send_booking_deposit_test, test_id(UUID), receiver(등록 운영자 번호), confirm_test=true를 보냅니다. 최초 1건만 실제 발송하고 같은 test_id는 중복 발송 없이 상태를 반환합니다. 시험 예약은 booking_journey_trials에 별도 저장하며, 실제 bookings/orders/수납 장부/달력은 변경하지 않습니다. 링크는 24시간 후 만료되며 계좌 등록·실제 입금 기능을 제공하지 않습니다. 관리자 거래 알림 이력에서 TEST 번호로 실제 알림톡 수신 결과를 확인합니다.

전액 첫 입금은 예약 확정 알림의 수신 이후 반영돼도 완납 알림을 추가하지 않습니다. 부분 납부를 확인했거나 분할 수납 내역이 있는 경우에만 잔금 완납 안내를 생성합니다.
