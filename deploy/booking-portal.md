# 예약별 통합 안내

관리자 예약 목록 또는 문의의 연결 예약에서 **통합 안내**를 열고 **전용 링크 만들기**를 누릅니다. 이후에는 같은 링크를 확인·복사할 수 있습니다. 고객 안내문 복사도 클립보드 복사만 수행합니다.

## 고객 화면

통합 안내는 전용 스타일과 독립 모듈로 구성합니다. 공통 `site.js`는 전용 스타일에 없는 빠른 연락 바·카카오톡 SVG 등을 삽입하므로 이 페이지에서 불러오지 않습니다. 예약확정서와 환급 계좌 모듈은 공통 페이지 스크립트 없이도 동작합니다.

- `/booking/#booking=…` 전용 링크에서 예약 정보·발급된 예약확정서(PDF/이미지 저장), 보증금 입금 정보와 기한, 환급 예정일·계좌 등록, 입실 안내를 확인합니다.
- 계좌 등록과 보증금 입금 확인은 별개입니다. 대관료 결제 완료로 보증금 입금 확인을 처리하지 않습니다.
- 계좌 등록은 기존 은행·계좌번호·재입력·예금주·필수 동의 검증과 암호화 저장, 버전 충돌 방지, 환급 처리 중 수정 잠금, 보유기간 정책을 재사용합니다. 저장 후에는 마스킹된 계좌만 표시합니다.
- 1호는 기존 승인된 출입·와이파이·장비 안내를 표시합니다. **2호는 전용 안내 준비 중**으로 표시하며 1호 비밀번호·와이파이·장비 링크를 표시하지 않습니다.
- 일정 변경은 같은 링크에서 최신 예약 정보로 확인합니다. 예약확정서는 기존 발급 절차를 사용하며, 미발급 상태는 발급 준비 중으로 표시합니다.

## 접근과 폐기

- 예약마다 별도의 무작위 전용 토큰을 사용합니다. 기존 예약확정서 토큰·예약번호+전화 뒷자리·환급 계좌 토큰으로 통합 안내를 열 수 없습니다.
- 서버에는 토큰 해시와 암호문을 저장합니다. URL의 토큰은 쿼리가 아닌 fragment에 넣고, 화면 진입 즉시 주소창에서 제거합니다. 페이지·API는 캐시 금지와 no-referrer, 검색 제외를 적용합니다.
- 같은 탭의 새로고침을 위해 전용 토큰만 sessionStorage에 최대 24시간 보관합니다. 계좌 원문은 저장하지 않습니다. **이 기기에서 안내 닫기**를 누르면 화면·토큰·입력 내용을 지웁니다.
- 링크 유효기간은 발급 후 최소 30일 또는 이용 종료 후 90일 중 더 늦은 날입니다. 만료·취소·예약자 이름/전화 변경은 기존 링크 접근을 차단합니다.
- 잘못 공유한 링크는 관리자에서 기존 링크 폐기를 확인한 후 재발급합니다. 기존 통합 링크만 무효화하고, 등록 계좌·기존 확정서/계좌 링크는 유지합니다. 폐기·취소와 계좌 저장이 경합하면 같은 SQL 갱신 조건에서 저장을 거부합니다.

## 발송과 운영 데이터

- 기존 고객의 통합 링크를 자동 생성하거나 소급 발송하지 않습니다. 기존 자동 발송 설정·알림톡 템플릿·고객 메시지 경로도 변경하지 않습니다.
- 통합 안내 발급/조회 및 계좌 등록 경로는 기존 백그라운드 발송 tick을 실행하지 않습니다. 링크 발급 요청은 수납 이력 보정도 실행하지 않습니다.
- 명시적으로 전용 링크를 만드는 경우에만 해당 예약의 링크를 저장합니다. 환급 계좌 초대가 필요하면 기존 초대 발급 로직을 재사용하며, 기존 유효 초대는 보존합니다.
- `migrations/20261103_booking_portal.sql`은 빈 전용 링크 테이블과 인덱스만 추가합니다. 기존 예약·고객·발송 설정을 갱신하지 않습니다. 동일 SQL은 schema.sql과 자동 초기화 스키마에 포함합니다. 기존 DEPOSIT_ACCOUNT_KEY 설정을 사용합니다.

## 검증

`node --test tests/booking-portal.test.mjs` 및 전체 회귀 `node --test tests/*.test.mjs`, Functions 빌드로 검증합니다. 로컬 UI는 외부 요청을 차단한 메모리 DB와 가상 예약/계좌로 확인합니다. 실제 고객 링크 발급·발송이나 발송 설정 변경은 검증에 사용하지 않습니다.

초기 구현 단계에서는 로컬 구현 및 검증까지 수행했고, 아래 운영 반영 단계에서 배포했습니다.
