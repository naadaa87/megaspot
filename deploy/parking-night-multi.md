# 주차권 야간 자동 등록·여러 차량 통합 결제

## 변경 내용 · 2026-11-05

- 이용일은 기존과 같이 평일만 선택한다. 당일 구매·입차 요청은 10:00–23:50, 서버 자동 등록은 10:00–24:00에 5분 간격으로 실행한다. 주말·공휴일, 전날 입차·익일 연속 주차는 자동 처리하지 않는다. 일일권 자정 종료는 그대로다.
- 구매자 연락처와 이용일을 한 번 입력하고, 차량별 1/2/3시간권 또는 일일권을 최대 10대까지 선택한다. 전체 차량번호를 각각 재입력한 뒤 합계로 PayApp 결제 한 건을 만든다.
- `orders`와 `payapp_payments`는 통합 결제 한 건만 저장한다. `parking_batches`는 구매 내역 접근을 검증하고, `parking_orders.payment_oid`는 차량별 등록 주문을 결제에 연결한다. `vehicle_price`로 차량별 금액을 보존한다. 기존 단일 차량 주문·구매 링크·완료 이력은 그대로 조회한다.
- 결제 통보는 서명·nonce·원 결제 총액을 검증한다. 차량별 결제 알림과 관리자 문자는 같은 DB 트랜잭션에서 중복 없이 적재한다. 각 차량의 실제 입차ID·전체 번호·무료 1시간 이력·유료 원가·등록 결과를 따로 대조한다. 기존 주문당 원가 한도와 중복 등록 방지는 유지한다.
- 차량별 입차·취소 문의는 해당 차량에만 기록한다. 실제 통합 결제 일부 환불이 통보되면 차량별 환불 대상을 임의 추정하지 않고 모두 자동 등록 보류한다. 구매 내역과 관리자에 통합 결제번호·취소 확인 필요 상태를 표시한다. 전체 환불이 검증되면 차량별 원금으로 전체 취소 알림을 적재하며 결제 원장은 한 번만 집계한다.

## 결제 완료 안내

기존 승인 템플릿 UN_2583에는 18시 마감 문구가 있어 그대로 야간 구매에 발송하지 않는다. 사용자는 새 알림톡 심사 중 결제 완료만 LMS로 발송하는 것을 승인했다. `parking-paid/send`는 고정 발신번호·거래 안내 본문·수신 번호 형식을 제한하고, 지속 원장으로 중복·응답 불명 재발송을 차단한다. 문자에도 차량별 구매 내역 링크를 포함한다. 등록 완료·취소 등 나머지 6종은 기존 승인 알림톡과 SMS 대체 발송을 유지한다.

새 템플릿은 `UN_3966` / 메가스팟_주차권_결제완료_자동등록_v2로 등록했고 웹 대체 문자 발송도 유지했다. 확인 시 검수 중이다. 문구·버튼은 `config/parking-paid-alimtalk.v2.json`에 보관한다. 승인된 본문·버튼 일치와 운영자 시험 수신을 확인한 뒤 기존 결제 완료 템플릿을 교체한다. 기존 `PARKING_PAID_SMS=false` 설정이 있으면 임시 문자 경로가 꺼지므로, 운영 배포 전에 해당 설정이 없는지 확인한다.

## DB 적용

운영 프로젝트는 Cloudflare의 Naadaa87 계정 `ac3d1b695a1c4e305f17b6caf34f6b4f`, DB는 megaspot-db `3f0aa07f-5d18-42f5-a45d-c89bbab99f28`이다. 과거 안내서 전용 계정 캐시와 구분한다.

1. 운영 DB 내보내기와 주차 주문·알림·조회 링크·문자 건수를 기록한다. 2026-11-05 콘솔에서 확인한 사전 복원 지점: `00000523-000006a5-0000511a-780c9f62817890f721e6e2b00b1518ad`.
2. `migrations/20261105_parking_batches.sql`을 한 트랜잭션으로 적용한다. 기존 단일 결제 외래키 제약을 차량 등록 단위로 바꾸면서 모든 기존 행을 복사한다. 실제 외래키 그래프를 검사하고 복사본을 원래 이름으로 교체한다. 적용 버전·기존 스키마 검사가 재실행을 막는다.
3. 이력 건수와 `PRAGMA foreign_key_check`를 확인한다. 원본 백업은 저장소에 올리지 않는다.
4. 사이트를 배포하고 별도 서버의 알리고 모듈과 아마노 타이머를 갱신한다. 사이트 공개 설정·서명된 처리 대상 조회·관리자 기존 주문 조회·서버 서비스 결과를 확인한다. 가짜 주문·추가 실결제·아마노 시험 등록·시험 문자를 생성하지 않는다.

## 검증

주차 구매·통합 결제·위변조·보안 링크·기존 데이터 이관·차량별 무료 배정·전체/부분 환불·고객 문자·관리자 알림·아마노 API/작업자/서버 관련 테스트 90개 통과. 로컬 구매 화면에서 차량 2대(4,000원 + 8,000원)를 합계 12,000원으로 확인하고 각 차량의 재입력 단계까지 검증했다. 실제 결제 API 호출은 차단했다.

운영 DB 이관을 완료했다. 기존 orders 7건·parking_orders 2건·고객 알림 3건·조회 링크 3건·관리자 문자 2건을 모두 보존했고, 별도 주차 주문 백업 2건·외래키 오류 0건을 확인했다. 최종 운영 확인 증빙은 `outputs/parking-multi-20261105/`에 보관한다.

## 추가 통합 검증 · 2026-11-05

`tests/parking-flow.test.mjs`는 통합 구매 API → 서명된 PayApp 결제 통보 → DB 알림 트리거 → 서명된 자동 처리 API → 실제 아마노 HTTP 어댑터·작업자 → 차량별 완료 알림과 전달 결과까지 연결한다. 외부 PayApp·아마노·알리고 응답은 전부 모의 처리하고 허용되지 않은 외부 요청은 실패시킨다. 실제 주문·할인 등록·문자 비용은 만들지 않는다.

2대 1시간권·2시간권의 12,000원 결제 한 건, 차량마다 무료 선등록, 유료 추가분 3,000원만 차감, 기존 무료 사용의 중복 방지, 다른 차량의 늦은 입차 후 다음 주기 등록, 완료 알림톡 실패 후 대체 문자 전달, 두 관리자에게 잔액 부족·등록 결과 불명 알림, 응답 유실 후 재실행 중복 방지를 검증했다. 기존 90개와 추가 6개를 합쳐 96개 통과했다.

통합 결제의 차량별 관리자 알림을 확인 처리할 때 결제 부모 주문을 조회하도록 수정했다. 관리자 결제 문자도 직접 등록 지시 대신 서버 자동 처리·관리자 상태 확인으로 안내한다. 운영 서버 읽기 전용 확인에서는 실제 처리 완료 주문이 없으므로 실차·실결제·실수신 성공으로 표시하지 않는다. 실차 검증에는 입차한 차량 2대와 각 주차권, 실제 결제 및 수신 확인이 필요하다.

## 다음 실주문 확인 · 2026-11-06

사용자는 현재 입차 차량이 없으므로 다음 실제 여러 차량 주문에서 검증하도록 요청했다. 감시 기준은 UTC `2026-11-06 01:39:02` 이후 정상 결제된 첫 2대 이상 통합 주문이다. 과거·테스트·미결제·환불 주문은 제외한다.

서명된 자동 처리 API의 `audit-batch` 작업은 조회만 수행한다. 다음 주문의 차량 끝번호·등록 상태·무료 배정·실제 차감 원가·고객 알림 및 관리자 두 번호의 문자 전달 상태를 조회한다. 이름·전화번호 전체·전체 차량번호·구매 조회 키는 반환하지 않는다. 운영시간 외에도 과거에 기록된 결과를 읽을 수 있어 컴퓨터가 꺼졌던 동안의 처리도 추후 대조한다.

서버 `/opt/megaspot-amano/audit-next-batch.mjs`는 기존 암호화 작업 원장의 무료 우선 적용 순서·기존 무료 사용·할인 이력·차감액 증빙과 사이트 상태를 대조한다. `node --env-file=/etc/megaspot-aligo.env /opt/megaspot-amano/audit-next-batch.mjs --since='2026-11-06 01:39:02'`로 확인한다. 결과는 `no_order`, `waiting`, `attention`, `verified`이며, 등록·결제·추가 문자·환불을 실행하지 않는다. 고객 결제 안내 및 등록 완료 안내의 전달과 관리자 두 수신 번호 전달까지 모두 확인돼야 `verified`다.

이 채팅 정기 확인은 15분 간격으로 위 조회만 수행한다. 주문 없음·입차 전·전달 결과 대기는 실주문 성공으로 보고하지 않는다. 다음 실제 통합 주문의 성공 또는 확인할 문제가 확정되면 결과를 보고하고 이 확인 작업을 종료한다. 기존 컴퓨터용 아마노 등록 자동 작업은 계속 일시정지한다. 서버 등록·기록·오류 문자는 컴퓨터 전원과 무관하지만 이 로컬 채팅의 예약 확인은 컴퓨터·Codex 앱 실행이 필요하다.

### 서버 검증·관리자 결과 문자로 전환

2026-11-06 사용자가 검증도 컴퓨터 전원과 무관하게 서버에서 처리하고 두 관리자에게 결과 문자를 보내도록 명시적으로 요청했다. 위 로컬 확인 작업은 서버 전환이 검증된 뒤 삭제한다. 기존 컴퓨터용 실제 등록 자동 작업은 PAUSED를 유지한다.

`megaspot-parking-watch.timer`가 5분 간격으로 `watch-next-batch.mjs`를 실행한다. 감시 기준 UTC `2026-11-06 01:39:02`는 유지하며, 첫 실제 2대 이상 통합 주문이 발견되면 주문번호를 고정한다. 이후 취소·부분 환불이 생겨도 다른 주문으로 바꿔 성공으로 오인하지 않는다. 주문 없음·단순 대기는 새 문자를 발송하지 않는다. 이상 중간 결과는 한 번만, 최종 성공 또는 미완료 결과는 별도로 안내한다. 조회 장애는 3회 연속일 때만 확인 필요 문자로 구분한다.

문자 수신은 기존 서버 승인 목록의 두 번호(끝번호 1886/9580)를 사용한다. `[메가스팟 주차권 검증 완료]` 또는 `[메가스팟 주차권 검증 확인 필요]`에 차량 끝번호·권종·무료 우선/기존 사용·실제 차감 및 고객·관리자 안내 전달 결과를 담는다. 기존 알리고 요금이 차감된다. 가짜 주문·시험 문자를 만들지 않는다. 검증 과정은 아마노 등록·결제·환불·충전을 호출하지 않는다.

상태와 수신자별 메시지는 기존 암호화 디렉터리의 `next-batch-watch.enc`에 저장한다. 고정 요청 ID를 발송 전에 기록하고 기존 문자 서버의 SQLite 중복 방지 원장을 거친다. 접수 불명은 같은 ID로만 최대 3회 확인하며 새 ID로 재발송하지 않는다. 두 관리자에게 최종 결과의 실제 전달이 확인돼야 `completed`가 되고 이후 회차는 조회·발송 없이 종료한다. 실패·불명 전달은 성공으로 처리하지 않고 원장을 보존한다.
