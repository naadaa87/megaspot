# 보증금 알림톡 운영 (2026-11-03)

관리자: https://megaspot.kr/admin/#deposit-notifications

| 종류 | 자동 발생 시점 | 알리고 코드 |
|---|---|---|
| 보증금 입금 안내 | 새 예약 확정, 아직 보증금 미입금 | UN_2759 |
| 환급 계좌 등록 요청 | 보증금 입금 확인 또는 입금된 예약 신규 확정 | UN_2760 |
| 환급 완료 안내 | 관리자의 실제 송금 완료/0원 정산 완료 기록 | UN_2761 |

3종은 2026-11-03 메가스팟 채널에 등록·검수 신청했습니다. 신청 당시 모두 REQ. 최신 상태는 관리자 **3종 승인 상태 확인** 또는 알리고에서 확인합니다.

## 시작 순서

1. 종류별 템플릿 코드와 본문·버튼이 일치하고 승인되었는지 확인합니다.
2. 운영자 번호로 3종을 각각 시험 발송하고, 접수뿐 아니라 실제 수신 성공을 확인합니다. 시험은 예시 예약이며 계좌 버튼은 예시 링크입니다. 실제 고객 계좌 링크를 운영자에게 전달하지 않습니다.
3. 기존 서버 `ALIGO_LIVE_ENABLED` 허용 및 종류별 시험 성공이 확인된 뒤 관리자에서 세 단계 선택·자동 발송 활성화·설정 저장을 합니다.
4. 자동 발송은 그 이후 **새 상태 전환**부터 시작됩니다. 기존 예약을 소급 일괄 발송하지 않습니다. 실제 보증금 입금 확인과 은행 송금은 운영자가 합니다.

## 동작

- 알림 발생은 DB 트리거에서 예약/입금/환급 변경과 같은 트랜잭션으로 기록합니다. 직접 등록 예약, 연결 문의의 체크, 온라인 결제 후 생성된 예약에 동일하게 적용합니다.
- 매일 한국시간 09:00–21:00에 고객 발송합니다. 야간 발생 건은 다음 주간에 발송합니다.
- 보증금은 예약 확정서 → 최근 연결 견적 → 150,000원, 입금 기한은 이용일 3일 전입니다. 확정 시 이미 기한이 지난 경우 확정 발생일로 안내합니다.
- 이미 입금되면 대기 중 입금 안내 취소, 계좌가 등록되면 등록 요청 취소. 취소·반환 완료·연락처/예약 변경·7일 경과 안내도 취소합니다.
- 환급 완료 안내는 환급 원장의 확정 금액과 완료 ID로 검증합니다. 차감액·최종 환급액·처리일을 표시하며, 0원은 전액 차감 정산임을 안내합니다.
- 계좌 요청 버튼은 예약별 기존 초대 발급 기능을 이용합니다. 링크 토큰을 발송 이력·로그·공개 파일에 저장하지 않습니다. 전체 고객 계좌번호는 알림톡에 넣지 않습니다.
- 접수와 실제 도착을 구분하고, 전송 ID·수신자 해시·발신 프로필·템플릿을 대조합니다. 결과 불명은 자동 재전송하지 않습니다. 알리고 미접수를 직접 확인하고 24시간 경과 후 미발송 기록 → 명확한 실패 상태에서 재시도할 수 있습니다.
- SMS/LMS 대체 발송은 OFF입니다. 기존 주차권 7종의 대체 문자 설정을 변경하지 않습니다.
- 정기 처리는 기존 고정 IP 연결 서버의 deposit-tick.mjs와 megaspot-deposit-notifications.timer를 이용합니다. 기존 서명 키를 사용하며 새 API 키·인증 범위를 만들지 않습니다. API 요청 후에도 같은 작업을 백그라운드에서 확인합니다. DB 임대로 전체 처리 빈도를 1분당 1회 제한하고 메시지별 조건부 잠금으로 중복 발송을 막습니다.
- 정기 처리 경로는 HMAC 서명·1분 유효시간을 확인하고 고객 개인정보를 반환하지 않습니다. 상태 조회는 읽기 전용입니다. 사용자 에이전트 변경이나 방화벽 우회는 구현하지 않습니다.
- 서버와 관리자 스위치는 기본 OFF. 승인·시험 수신이 없으면 고객 자동 발송을 켤 수 없습니다. 환경/템플릿/암호화 키 변경은 기존 시험 성공을 무효화합니다.

## 계좌 미등록 고객 선택 재안내 (2026-11-05)

어드민 **보증금 환급 관리 → 계좌 미등록 고객**에서 보증금 입금 확인·환급 미완료·계좌 미등록·환급액이 남은 예약만 조회한다. 등록 정보 보유기간이 끝난 예약은 제외한다. 검색·이용일 범위는 그대로 사용할 수 있다. 보류 등 재안내 불가 건은 사유를 표시하고 선택을 막는다.

고객을 최대 20명 선택하거나 예약별 **계좌 요청 다시 보내기 · 미리보기**를 누른다. 승인된 UN_2760 문구·이름·수신번호를 확인하고 확인란에 체크한 다음 요청한다. 이 단계는 발송 대기 등록이며, 기존 발송 이력에서 실제 수신 결과를 확인한다. 09–21시 기존 발송 작업을 사용하며 야간 요청은 다음 발송 시간까지 대기한다. 기존 자동 발송 설정·시험 수신·실제 템플릿 승인 검사를 그대로 적용한다.

미리보기는 10분간 유효하고 고객 등록 링크를 발급하지 않는다. 요청 시 미리보기 이후의 예약·연락처·입금·계좌·환급·발송 이력 변경을 다시 확인한다. 발송 직전에도 계좌 등록 여부를 확인한다. 처리 중·결과 미확인 이력 또는 최근 1시간 내 수신 성공 이력이 있으면 재안내를 막는다. 확정 실패는 새 미리보기 후 재요청할 수 있다. 기존 유효한 전용 링크는 재사용한다. 미리보기 ID 소비와 예약 상태를 검사하는 INSERT, outbox 고유키로 중복 클릭·동시 요청을 막는다. 이미 등록·반환 완료·전액 차감·취소·보류·등록 유효기간 경과 예약에는 발송하지 않는다.

스키마는 `migrations/20261105_deposit_account_reminders.sql`과 공통 스키마 초기화에 포함되어 API 첫 요청 시 적용된다. 별도 고객 데이터 수정이나 과거 건 자동 일괄 재발송은 없다.

검증: 전체 Node 테스트 857개 통과, Pages Functions Worker 빌드 통과. 새 회귀 테스트 16개는 선택 범위, 로그인 보호, 등록·연락처·입금·예약 상태 변경, 미승인·만료·설정 중지, 중복 요청, 실제 발송 직전 제외, 실패·결과 불명·최근 성공을 확인한다. 모바일 390px/320px에서 실제 모듈의 선택·미리보기·확인·대기 등록·모의 수신 성공 및 가로 넘침 없음/주요 버튼 44px 이상을 확인했다. `QA_REMINDERS=1 node tests/helpers/combined-receipts-preview.mjs`로 재현하며 공급자 요청은 전부 로컬 모의 응답이다. 이 검증으로 실제 고객 알림톡은 발송하지 않는다.

### 목록의 재안내 이력

계좌 미등록 고객 카드에서 마지막 요청 시각(occurred_at, 한국 시간), 누적 요청 횟수, 수신 성공 횟수, 최신 상태, 결과 갱신 시각과 오류 사유를 표시한다. 요청 횟수는 live/account만 집계하며 취소·시험 발송·다른 안내 종류는 제외하고 대기·실패는 포함한다. 요청 시각은 수신 성공 시각과 구분한다. 이력 없는 고객은 요청 0회/수신 성공 0회/미발송으로 표시한다. 기존 이력 및 재안내를 모두 합산하며 등록 여부나 실제 발송 동작은 변경하지 않는다.

### 계좌 미등록 목록의 발송 상태 필터

목록 상단의 알림톡 발송 상태에서 전체/미발송/최근 발송 실패를 선택한다. 미발송은 live/account 요청 이력이 없는 고객(취소만 있는 경우 포함)이며 대기·처리 중·결과 미확인·성공·실패는 포함하지 않는다. 최근 실패는 최신 live/account 이력이 failed인 고객이며 후속 요청이 대기 중이면 제외한다. 시험·다른 안내 종류는 판단에서 제외한다. 필터는 SQL LIMIT 전에 적용하며 검색·날짜 범위를 유지한다. 필터 전환은 고객 선택을 초기화한다. 모바일 가상 고객으로 실패 1건/미발송 0건 전환과 가로 넘침 없음을 확인했다. 전체 테스트 859개 및 Functions 빌드 통과. 실제 고객 발송 없음.

### 모바일 필터→선택→미리보기→재요청 연속 점검

390px에서 미발송 가상 고객 1명 수동 선택, 미리보기 수신자 확인, 확인란 체크, 요청·대기 등록 및 모의 수신 성공을 확인했다. 320px에서 실패 고객 1명 필터·일괄 선택·미리보기·동의·재요청·모의 수신 성공을 확인했다. 각각의 처리 후 해당 필터에서 제외되며, 전체 목록 복귀 시 두 고객의 최신 결과가 수신 성공으로 표시된다. 실제 공급자 전송은 전부 모의 응답이며 고객 발송은 없다.

빈 필터 결과에는 대기 전환으로 목록에서 빠질 수 있음을 안내하고 전체 미등록 목록 복귀 버튼을 제공한다. 로딩 시작 시 이전 목록과 선택을 지우고 선택 가능한 고객이 없으면 일괄 선택도 비활성화하여, 필터 전환 중 이전 고객이 선택되는 일을 막는다. 관련 회귀 테스트 18개 통과, JS 구문·diff 검사 통과.

### 발송 대기·결과 확인 필요 필터

계좌 미등록 목록에 발송 대기·처리 중(queued/sending), 결과 확인 필요(accepted/unknown/review) 필터를 추가했다. 최신 요청뿐 아니라 미완료 상태로 남은 이전 live/account 이력도 EXISTS로 조회한다. 시험 및 다른 종류 안내는 제외하며 SQL LIMIT 전에 적용한다. 미완료 이력이 있는 고객의 중복 재안내는 제한한다. review도 목록·미리보기·발송 직전의 재안내 제한에 포함한다.

모바일 가상 고객으로 각 필터 1건 조회, 해당 고객 선택 비활성화, 가로 넘침 없음을 확인했다. 전체 테스트 860개와 Functions 빌드 통과. 실제 고객 발송 없음. 재현: `QA_REMINDERS=1 QA_HISTORY=1 QA_PENDING=1 node tests/helpers/combined-receipts-preview.mjs`.

### 모바일 미완료 상태 가독성

320px/390px 실제 모듈의 가상 대기·확인 필요 고객을 점검했다. 이전 unknown 이력과 최신 failed 이력이 공존할 때 최근 결과만으로 판단하는 혼동을 줄이기 위해 카드 위에 미완료 이력의 대기·처리 중 건수와 결과 확인 필요 건수를 따로 표시한다. 최신 결과·시각·요청 횟수는 그 아래 그대로 표시한다. 조회 전용 대기/확인 필터에서는 선택 도구를 숨기고 해당 상태를 설명한다. 재발송 제한은 유지한다. 가로 넘침 없음 확인. 모의/실제 고객 알림톡 발송 없음. 관련 테스트 19개 통과.

### 고객별 발송 결과 다시 조회

계좌 미등록 고객 카드에 확인 필요 이력(check_count)이 있으면 **발송 결과 다시 조회**를 표시한다. POST `deposit-notifications/account-reminders/refresh`에 예약번호를 전달하면 해당 예약의 live/account accepted·unknown·review 이력을 최대 20건 조회한다. 기존 접수번호를 사용한 알리고 history/detail 조회만 실행하며 발송·링크 발급·재시도는 하지 않는다. 템플릿·발신 프로필·수신번호 해시·설정 해시를 대조해 확정 성공/실패만 반영하고, 동시 변경 시 상태를 덮어쓰지 않도록 조건부 UPDATE를 사용한다. 결과 미확정·외부 오류·접수번호 없음·설정 불일치는 상태 유지와 안내를 반환한다. review는 안내 내역에서 예약 변경 확인이 필요하다는 안내만 반환한다. 자동 조회도 동일한 상태 보호 함수를 사용한다.

조회 후 현재 목록을 갱신하고 결과 요약을 표시한다. 성공/실패로 확정된 고객은 확인 필요 필터에서 제외된다. 이전의 다른 미완료 이력이 있으면 남아 있다. 모바일 390px에서 unknown 가상 고객 → 재조회 → 수신 성공 → 필터 0건 → 전체 목록의 성공 반영을 확인했다. 공급자 응답은 모의이며 실제 고객 발송 없음. 전체 테스트 865개, Functions Worker 빌드 통과. 재현: `QA_REMINDERS=1 QA_HISTORY=1 QA_REFRESH=1 node tests/helpers/combined-receipts-preview.mjs`.

### 모바일 결과 조회 버튼·피드백 개선

조회 버튼을 파란 테두리·배경으로 구분하고 600px 이하에서 전체 너비·48px 높이로 표시한다. 조회 중 문구와 aria-busy 및 중복 클릭 제한을 제공한다. 결과 안내는 목록 바로 위에 배치하고 완료·오류 시 포커스와 스크롤을 이동하여 고객 카드가 필터에서 빠져도 결과를 놓치지 않게 한다. 목록 갱신 실패는 결과 조회 실패와 구분한다. 빈 목록은 실제 처리 상태와 관계없이 전체 목록에서 최신 상태를 확인하도록 안내한다.

320px 실제 모듈+가상 고객에서 버튼 239×48px, 조회 성공→확인 필요 0건→결과 안내 화면 내 노출/포커스, 가로 넘침 없음을 확인했다. 390px 추가 점검은 브라우저 응답 불안정으로 완료하지 못했다. 관련 회귀 테스트 24개 및 JS 구문/diff 검사 통과. 실제 고객 발송 없음. QA_RESULT=failed 옵션으로 실패 결과 모의 재현을 지원한다.
