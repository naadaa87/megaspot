# 알리고 고정 IP 연결

알리고 계정의 ‘발송 서버 IP’ 인증을 유지하는 연결 서버입니다. Cloudflare Pages의 변동 출발 IP를 넓게 허용하지 않습니다. 실제 배포 상태는 아래 운영 기록을 확인합니다. 기존 서버 `158.247.232.204`의 SSH 접속과 Caddy 도메인 `relay.naranhistory.com`을 확인했습니다. 기존 서비스는 그대로 두고 `/megaspot/aligo` 경로를 별도 Node 서비스로 연결합니다.

## 설치할 서버

- 고정 공인 IP가 있는 사용자 소유 서버. 해당 IP를 알리고에 등록합니다.
- Node.js 22.13 이상, 지속 저장 디스크, HTTPS 리버스 프록시.
- `server.mjs`는 `127.0.0.1:8787`에만 바인딩합니다. 외부에는 HTTPS `https://relay.naranhistory.com/megaspot/aligo`만 연결합니다.
- `data/aligo-relay.sqlite`는 영구 디스크에 보관합니다. 전송 요청 ID와 결과를 저장해 재시작·중복 요청에도 같은 발송을 다시 실행하지 않습니다. 결과 미확인 건을 임의 삭제하면 안 됩니다.

## Secret 환경 변수

서버: `ALIGO_USERID`, `ALIGO_API_KEY`, `ALIGO_SENDER_KEY`, `ALIGO_SENDER`, `ALIGO_RELAY_SECRET`(32자 이상 무작위), `ALIGO_TEMPLATE_CODES=UN_2584,UN_2583,UN_2586,UN_2587,UN_2588,UN_2589,UN_2591,UN_2592`.

Cloudflare Pages 운영 환경: `ALIGO_RELAY_URL=https://relay.naranhistory.com/megaspot/aligo`, 같은 `ALIGO_RELAY_SECRET`, `ALIGO_SENDER_KEY`, `ALIGO_SENDER`. **알리고 API 키는 연결 서버에만 보관합니다.** Cloudflare에서 API 키를 보내지 않습니다. 설정 변경 후 기존 프로젝트를 다시 배포합니다.

`ALIGO_LIVE_ENABLED=true`는 연결·승인·시험 수신 확인 후 설정합니다. 어드민의 고객 발송·자동 발송 설정은 별도로 기본 OFF입니다. Preview 배포에 운영 비밀값을 복사하지 않습니다.

## 확인 순서

1. 서버 환경 변수와 지속 디스크 설정 → `node server.mjs`를 프로세스 관리자로 실행.
2. 기존 TLS 도메인에 `/megaspot/aligo` Caddy 경로 연결. 해당 고정 IP는 알리고에 이미 등록되어 있습니다.
3. 메가스팟 어드민에서 ‘승인 상태 확인’으로 서명·연결·본문·버튼 일치 확인.
4. 템플릿 `UN_2584` 승인 후 운영자 실제 시험 수신 및 전송 결과 확인.
5. 확인한 호점만 선택하고 고객 발송 활성화. 기존 확정 고객은 미리보기 후 따로 일괄 발송.

허용 API는 템플릿 조회, 메시지 결과 조회, 단일 수신자 알림톡 전송뿐입니다. HMAC-SHA256 서명·1분 요청 유효시간·고정 수신자 프로필·허용 템플릿 목록·지속 중복 방지를 적용합니다. 예약 시설 안내의 대체 문자는 OFF이며, 사용자가 요청한 주차권 7종은 대체 문자 본문을 필수로 검사하고 ON으로 발송합니다. 대체 문자의 상세 결과는 해당 알림톡 이력에서 확인된 SMS 메시지 ID만 조회합니다. 운영자가 확인하지 않은 알리고 IP 범위를 추가하거나 기존 다른 서비스 키를 교체하지 않습니다.


## 운영 준비 기록 · 2026-11-03

- 알리고 등록 IP `158.247.232.204`와 이 맥의 기존 SSH 호스트 기록을 대조하고, 기존 키로 접속을 확인했습니다. 서버 호스트명은 `relay`, Node 버전은 `22.22.1`입니다.
- 기존 서비스는 Caddy와 `naranhi-commerce`이며 둘 다 정상 동작 중임을 확인했습니다. 기존 `/socialfactory/aligo/send` 경로를 변경하지 않습니다.
- `/opt/megaspot-aligo/`에 전용 소스·systemd unit·Caddy 경로 설정을 별도로 준비했습니다. 이 서버의 실제 Node 환경에서 모의 API 테스트 6개와 Caddy 임시 설정 검증을 통과했습니다.
- 사용자 본인 인증과 연결 승인을 완료한 뒤 기존 알리고 API 키를 재사용했습니다. 원본 API 키는 서버의 `/etc/megaspot-aligo.env`에 root 전용 권한으로 저장하고, 전용 사용자 `megaspot-aligo`의 systemd 서비스를 활성화했습니다.
- Caddy 기존 설정을 비공개 백업하고 검증한 뒤 `/megaspot/aligo` 경로를 추가했습니다. 기존 Caddy·commerce 서비스와 전용 릴레이 모두 정상 동작합니다. 로컬 서비스와 공개 HTTPS 경로에서 실제 템플릿 조회가 성공했고, `UN_2584`는 `REQ`(검수 중)입니다. 실제 메시지는 발송하지 않았습니다.
- Cloudflare 운영 환경에 연결 변수 5개를 저장했습니다. 서버 인증 키와 메가스팟 발신 키는 Secret으로 보관하고 `ALIGO_LIVE_ENABLED=false`로 유지합니다. 알리고 원본 API 키는 Cloudflare나 저장소에 복사하지 않습니다. 환경 변수 적용을 위해 이 운영 기록과 함께 다시 배포합니다.
- 운영 관리자에서 조회 중 발견한 Workers의 `redirect: 'error'` 미지원 문제를 수정했습니다. `manual`로 요청하고 3xx 응답을 거부해 다른 주소로 인증정보를 전달하지 않습니다. 안내 발송·릴레이 관련 테스트 32개를 통과했습니다.
- 실제 발송 전에는 `UN_2584` 승인, 호점별 안내 확인, 운영자 시험 수신이 필요합니다. 결과 조회는 이 릴레이가 만든 메시지 ID만 허용해 다른 서비스의 발송 내역을 읽지 못하게 합니다.

## 주차권 알림 자동 처리

- `parking-tick.mjs`와 `megaspot-parking-notifications.timer`는 1분마다 주차 발송 대기를 확인합니다. 서명 키는 기존 서버 환경 파일에서 읽고 메가스팟의 고정 HTTPS 주소만 호출합니다.
- DB 트리거는 주차 알림이 활성화된 이후 새 상태 전환만 같은 트랜잭션으로 기록합니다. 과거 주문은 소급 발송하지 않습니다.
- 관리자 → 주차권 관리 → 주차권 알림톡·문자에서 7종 승인·본문·버튼 일치를 확인합니다. 운영자 본인 번호와 본인 주차 주문으로 실제 유료 결제 완료 시험 수신을 확인한 다음 서버 운영 발송 허용과 주차 자동 발송을 켭니다. 예약 안내와 주차 알림의 활성화 설정은 각각 관리합니다.
- 응답 불명은 자동 재전송하지 않습니다. 알림톡 실패 시 알리고가 SMS/LMS를 대체 발송하며 애플리케이션에서 별도 문자를 다시 보내지 않습니다.
- 구매 내역 버튼은 주문별 알림 전용 키를 사용합니다. DB에는 키 해시만 저장하고 키를 로그에 기록하지 않습니다. 링크는 이용일 또는 발급일 중 늦은 날로부터 7일 뒤 만료됩니다.

### 주차권 연결 적용 · 2026-11-03

기존 서버에서 연결 모듈 테스트 8개를 통과한 뒤 기존 코드를 백업하고 주차 템플릿 7종 허용과 대체 문자 결과 조회를 적용했습니다. 기존 API 키·계정·발신프로필·발신번호는 교체하지 않았습니다. 공개 HTTPS 경로에서 7종 실제 조회가 모두 성공했고 현재 상태는 전부 REQ(검수 중)입니다. 정기 처리 실행은 사이트 배포 확인 후 시작하며 고객 발송 잠금은 유지합니다.

### 운영 사이트 배포 확인

주차 알림 모듈과 관리자 화면을 운영 사이트에 배포했습니다. 로그인된 관리자 화면에서 기존 알리고 연결 등록 상태 및 7종 실제 조회, 본문·버튼 일치, 고객 자동 발송 OFF를 확인했습니다. 7종은 모두 REQ(검수 중)입니다. 정기 처리 서비스·타이머 파일은 서버에 설치했지만 아직 타이머를 켜지 않았습니다. 서버의 기본 Python HTTP 요청이 Cloudflare 1010으로 거절되어 자사 User-Agent를 사용하는 읽기 전용 조회의 사용자 승인을 기다립니다. 자동 승인 검토가 스케줄 실행과 User-Agent 변경 후 조회를 차단했으므로 우회 실행하지 않았습니다. 접근 확인 및 승인·운영자 시험 수신이 끝나기 전 고객 발송을 켜지 마세요.

### 고객 주차 알림톡 운영 시작 · 2026-11-04

- 위 11월 3일 기록 이후, 실제 주차 7종이 모두 APR이며 본문·버튼이 일치하는 것을 재확인했습니다. 전역 운영 발송 허용도 이미 켜져 있었습니다.
- 사용자가 시험과 운영 발송을 요청했습니다. 관리자 본인 번호 끝자리 1886과 해당 번호의 기존 시험 주차 주문으로 결제 완료 알림톡 1건을 발송했고, 실제 결과가 `delivered`(알림톡 도착)인 것을 확인했습니다. 새 결제나 아마노 등록은 만들지 않았습니다.
- 관리자 주차 전용 고객 자동 발송을 켰습니다. 서명된 상태 조회에서 `enabled`, `live_allowed`, `configured`, `test_delivered` 모두 true이며 7종 모두 ready입니다. SMS/LMS 대체 발송은 유지합니다.
- 서버 발송기를 현재 소스로 갱신하고 `MegaspotParking/1.0 (+https://megaspot.kr)` 요청 식별자를 적용했습니다. `megaspot-parking-notifications.timer`를 enabled/active로 설정했으며, 1분 간격으로 실행합니다. 활성화 후 서비스 Result=success, ExecMainStatus=0, 다음 실행 예약을 확인했습니다. 컴퓨터·Chrome이 꺼져 있어도 서버에서 실행됩니다.
- 새로 발생하는 주차 결제·입차 접수·등록 완료/문제·취소 문의·환불 이벤트를 안내합니다. 과거 주문을 소급 적재하지 않습니다. 고객이 입차 요청 버튼을 누르지 않고 서버가 실제 입차를 확인해 등록하면 입차 접수 안내 없이 등록 완료 안내가 갈 수 있습니다.
- 주차 알림·릴레이 관련 테스트 26개를 통과했습니다. 운영 확인 기록은 `outputs/parking-alimtalk-20261104/verification.json` 및 관리자 화면 증빙에 보관합니다.
