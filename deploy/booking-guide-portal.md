# 예약 확정 알림톡 · 통합 안내 연결

## 이번 작업의 적용 범위

예약별 통합 페이지로 이동하는 알림톡 버튼과 서버 발송 연결을 구현했습니다. 운영 자동 발송 설정, 기존 승인 템플릿, 기존 고객 발송 이력은 변경하지 않았습니다. 초기 로컬 검증 후 아래 운영 반영 단계에서 연결 코드를 배포했습니다. 신규 템플릿은 활성화하지 않았습니다.

알리고에는 별도 신규 템플릿 `메가스팟_예약통합안내_v1` / `UN_2935`(내부 번호 436350)를 등록했습니다. 2026-11-03 확인 상태는 **검수 중**입니다. 모바일·PC 버튼은 `https://megaspot.kr/booking/#booking=#{안내코드}`, 이름은 **예약 안내 확인**입니다. 기존 `UN_2584`를 수정하거나 교체하지 않았습니다.

## 미리보기와 모의시험

관리자 → 이용 안내 알림톡 → 예약 선택 후 **통합 안내 미리보기 (발송 없음)** 또는 **통합 안내 모의시험 (발송 없음)**을 누릅니다. 해당 예약의 전용 링크를 명시적으로 발급/재사용하며, 기존 예약 전체를 일괄 생성하지 않습니다.

- 문구에는 고객명·공간·날짜·시간·예약번호를 반영합니다. 버튼으로 확정서·보증금·환급 계좌·입실 안내를 확인합니다.
- 미리보기와 모의시험은 고객 발송용 preview_id를 생성하지 않습니다. 발송 대기/발송 이력도 생성하지 않습니다.
- 모의시험은 실제 발송에 쓰는 요청 구성 함수를 재사용하고, 링크가 가리키는 고객 API까지 내부 호출해 예약 일치를 확인합니다. 알리고 API를 호출하지 않으므로 **실제 수신 시험 성공이나 템플릿 승인 확인으로 취급하지 않습니다.**
- 새 준비 경로는 기존 백그라운드 발송 tick을 실행하지 않습니다.
- 같은 문의에 예약이 여러 개 있으면 각각 다른 링크로 연결합니다. 2호는 전용 안내 준비 중 상태를 유지합니다.

## 실제 발송 경로의 안전장치

- 현재 설정에 variant가 없으면 기존 시설 안내 방식입니다. 기존 본문·버튼·설정 해시·운영자 시험 성공 판정은 그대로 유지합니다. 모의시험 이후의 새 예약도 기존 자동 방식으로 처리됩니다.
- 새 방식은 별도로 `variant=booking-portal`을 선택하고 승인된 신규 코드·호점·암호화 설정·실제 운영자 수신 확인을 갖춘 경우에만 사용할 수 있습니다. 이번 작업에서 이 설정 저장을 실행하지 않았습니다.
- 실제 운영자 시험은 수신 번호와 예약 연락처가 같은 본인 예약을 지정하고 전용 링크 전달을 확인해야 합니다. 다른 고객의 링크를 임의 운영자 번호로 보내지 않습니다.
- 기존 안내 목적·예약 버전·중복 방지를 유지합니다. 새 템플릿을 준비했다고 과거 고객에게 다시 발송하지 않습니다.
- 원문 링크 토큰은 암호화된 portal 테이블 외에 미리보기/큐/이력 JSON에 저장하지 않습니다. 발송 스냅샷에는 링크 버전·해시·수신자 해시만 보관하고 버튼은 전송 직전에 복원합니다.
- 발송 직전 예약·연락처·링크 버전·만료·취소를 재검사합니다. 재발급/변경된 링크를 미리보기와 다른 새 링크로 몰래 바꾸지 않습니다. 마지막 큐 점유 SQL에도 버전·예약 상태·연락처 조건을 넣어 경합을 차단합니다.
- 대체 문자 요청은 기존과 동일하게 `failover=N`입니다. 결과 불명/접수 중의 재발송 잠금도 유지합니다.

## 운영 사용 전 남은 조건

1. 카카오에서 `UN_2935` 승인 후 실제 본문·모바일/PC 동적 버튼 일치 확인.
2. 고정 IP 발송 서버의 허용 템플릿 목록에 신규 코드 등록. 기존 허용 목록·Secret·타이머는 이번 작업에서 변경하지 않았습니다.
3. 사용자 지시에 따른 별도 설정 전환 및 운영자 본인 예약으로 실제 수신 시험. 모의시험만으로 고객 발송을 활성화하지 않습니다.
4. 별도 승인된 운영 배포·설정 적용. 신규 방식으로 소급 일괄 발송하지 않습니다.

## 검증과 외부 설정 저장 제한

신규 전용 테스트는 기존 설정/해시 보존, 발송 없는 미리보기/모의시험, 복수 예약 링크 분리, 신규 승인 검증, 운영자 본인 예약 제한, 실제 요청 구성, 토큰 비저장, 링크 재발급/취소/연락처 변경, 점유 SQL 경합, 새 예약 자동 경로, CRLF 본문, 암호화 키 누락을 확인합니다. 외부 전송은 가짜 인증정보와 모의 API로만 검증합니다.

알리고 신규 등록 뒤 표시된 대체문자 입력 화면의 저장 시도는 자동 승인 검토가 사용자의 ‘자동 발송 설정 변경 금지’를 이유로 차단했습니다. 해당 저장은 수행하지 않았습니다. 이후 읽기 전용 목록과 상세 확인에서 신규 `UN_2935`의 대체문자가 이미 **발송안함**임을 확인했으므로 추가 변경 없이 마쳤습니다.

최종 검증: 전용 테스트 14개, 분리 검증본 전체 테스트 417개 모두 통과, Functions 빌드 성공. 가상 1·2호 예약의 미리보기·모의시험과 각 버튼의 실제 로컬 고객 페이지 연결, 모바일 가로 넘침 없음(375px), 브라우저 오류 없음, 예약 선택 복귀를 확인했습니다. 로컬 감사 값은 외부 요청 0건·설정 원문 동일·발송 이력 0건·발송용 preview 0건·가상 링크 2건입니다. 가상 DB 서버는 종료했습니다. 기록은 `../../outputs/guide-portal-20261103/verification.json`, 등록 템플릿 명세는 같은 폴더의 `template.json`에 저장했습니다. 고객 전용 토큰은 검증 기록에 포함하지 않았습니다.
