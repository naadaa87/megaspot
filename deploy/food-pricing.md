# 출장뷔페 · 출장 케이터링 가격표

어드민의 각 서비스 화면에서 항목별 공급가·판매가를 수정하고 **가격표 저장·전체 반영**을 누른다. 마진은 판매가−공급가, 마진율은 마진÷판매가. 가격표는 D1 `settings.catering_pricing`, `settings.reception_pricing`에 버전과 함께 저장되며 동시 수정 충돌은 409로 막는다.

출장뷔페는 기존 공급가 산정 방식(저장된 1인 수수료, 바베큐 최대 인원 기준)을 초기 공급가로 가져온다. 첫 저장 후에는 항목별 공급가를 사용한다. 출장 케이터링은 원본 PDF의 네 코스·43종 개별/박스 메뉴 공급가와 사용자가 제공한 출장·세팅비를 초기 공급가로 사용한다. 50명 이하 테이블 출장·세팅비 공급가는 2026-11-03 사용자 확인에 따라 200,000원이다. 미입력은 0원과 다르며 마진을 계산하지 않는다. 출장뷔페 부가세 10%, 출장 케이터링의 기존 부가세 적용 여부 확인 기준을 유지한다.

공개 `/api/{catering,reception}/pricing`에는 판매가만 반환한다. 루트 미들웨어가 홈페이지 가격과 계산기 초기 데이터를 갱신하고, `/assets/docs/megaspot-{catering,reception}-guide.pdf`는 같은 저장 가격으로 제공한다. HTML·API·PDF는 `no-store`. 고객 제출 가격은 신뢰하지 않고 서버에서 현재 판매가로 재계산한다. 이미 저장·발행된 견적과 확정서는 저장 당시 금액을 유지한다. 관리자에서 구성을 명시적으로 다시 계산·저장할 때 최신 금액을 사용한다.

PDF 템플릿 재생성: 번들 Python으로 `tools/build_food_price_templates.py`를 실행한다. 두 고객용 PDF, 고정 길이 숫자 슬롯 템플릿과 슬롯 JS를 함께 배포한다. 금액만 같은 길이로 교체해 PDF 교차 참조·스트림 길이가 유지된다. PDF에 공급가·마진이 들어가지 않는다. 원가·메뉴·사진 변경 시에는 관련 데이터와 템플릿 생성 코드를 검토한다.

검증: `node --test tests/*.test.mjs`, Wrangler Functions 빌드, 실제 어드민 저장→새로고침→홈페이지→계산기→PDF 브라우저 확인. 운영 검증에는 고객 가격을 변경하는 테스트를 하지 않는다.

## 케이터링 공급가 확인 근거 (2026-11-03)

- 원본: 사용자가 제공한 `파티룸 케이터링 메뉴구성-1.pdf` (애드썸 케이터링), SHA-256 `0c75f64e53a261c7f4683ff13773c35d694170b8e7ffc2896067f753fed64596`.
- 2~3쪽: 라이트/클래식/프리미엄/시그니처 공급가 20,000/30,000/40,000/50,000원.
- 4쪽: 개별·박스 메뉴 24종, 5쪽: 19종. 메뉴 사진·이름·단위를 대조해 `functions/api/_reception_supplier_prices.js`에 원본 단가를 기록했다. 현재 판매가에서 역산하지 않는다. 단가의 30% 가산 후 100원 올림이 기존 판매가와 일치함을 검증한다. 예: 대만식 햄치즈 샌드위치 2,800→3,700원(마진 900원, 마진율 약 24.3%), 모둠 쿠키 1BOX 60,000→78,000원(마진 18,000원, 약 23.1%).
- 출장·세팅비: 이전 「출장 케이터링 PDF와 웹사이트 추가」 대화의 제공 방식별 금액. 도시락·박스 100명 이하/101~200명/201~300명은 100,000/150,000/200,000원. 테이블 51~100명/101~200명/201~300명은 250,000/300,000/350,000원. 50명 이하는 이번 사용자 확인에 따라 200,000원. 판매가를 가산하지 않았으므로 기본 출장·세팅비 마진은 0원이다.
- 공급가만 보완한다. 기존 판매가·부가세 기준·고객 견적 금액은 변경하지 않는다. 이미 관리자가 직접 입력한 공급가(0원 포함)와 판매가는 덮어쓰지 않는다. 운영 가격표에 남아 있는 미입력 공급가는 어드민에서 확인된 원본 단가를 입력해 저장한다. 이후 직접 비운 값은 미입력으로 유지된다.
