# 출장뷔페 · 출장 케이터링 가격표

어드민의 각 서비스 화면에서 항목별 공급가·판매가를 수정하고 **가격표 저장·전체 반영**을 누른다. 마진은 판매가−공급가, 마진율은 마진÷판매가. 가격표는 D1 `settings.catering_pricing`, `settings.reception_pricing`에 버전과 함께 저장되며 동시 수정 충돌은 409로 막는다.

출장뷔페는 기존 공급가 산정 방식(저장된 1인 수수료, 바베큐 최대 인원 기준)을 초기 공급가로 가져온다. 첫 저장 후에는 항목별 공급가를 사용한다. 출장 케이터링은 확인된 네 코스 공급가만 초기화하며, 미확인 출장비·개별 메뉴 공급가는 미입력이다. 미입력은 0원과 다르며 마진을 계산하지 않는다. 출장뷔페 부가세 10%, 출장 케이터링의 기존 부가세 적용 여부 확인 기준을 유지한다.

공개 `/api/{catering,reception}/pricing`에는 판매가만 반환한다. 루트 미들웨어가 홈페이지 가격과 계산기 초기 데이터를 갱신하고, `/assets/docs/megaspot-{catering,reception}-guide.pdf`는 같은 저장 가격으로 제공한다. HTML·API·PDF는 `no-store`. 고객 제출 가격은 신뢰하지 않고 서버에서 현재 판매가로 재계산한다. 이미 저장·발행된 견적과 확정서는 저장 당시 금액을 유지한다. 관리자에서 구성을 명시적으로 다시 계산·저장할 때 최신 금액을 사용한다.

PDF 템플릿 재생성: 번들 Python으로 `tools/build_food_price_templates.py`를 실행한다. 두 고객용 PDF, 고정 길이 숫자 슬롯 템플릿과 슬롯 JS를 함께 배포한다. 금액만 같은 길이로 교체해 PDF 교차 참조·스트림 길이가 유지된다. PDF에 공급가·마진이 들어가지 않는다. 원가·메뉴·사진 변경 시에는 관련 데이터와 템플릿 생성 코드를 검토한다.

검증: `node --test tests/*.test.mjs`, Wrangler Functions 빌드, 실제 어드민 저장→새로고침→홈페이지→계산기→PDF 브라우저 확인. 운영 검증에는 고객 가격을 변경하는 테스트를 하지 않는다.
