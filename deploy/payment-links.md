# 관리자 결제링크

관리자 `/admin/#payment-links`에서 대관비·출장뷔페·기타 청구의 고정 금액과 설명을 입력하고 고객에게 공유할 메가스팟 링크를 생성합니다. 고객은 메가스팟 로고, 판매자, 청구 내역, 이용 정보와 조건을 확인한 뒤 페이앱으로 이동합니다.

## 사용 흐름

1. 서비스와 결제 목적(예약금·잔금·전체 금액)을 선택합니다.
2. 제목, 부가세를 포함한 이번 결제 금액, 상세 설명을 입력합니다. 기본 설명은 수정할 수 있습니다.
3. 필요하면 이용일·공간·인원·시간과 기존 예약번호를 입력합니다. 날짜·시간·만료일은 한국 기준입니다.
4. 미리보기를 확인하고 링크를 생성합니다. 생성한 링크는 최근 목록에서 다시 복사하거나 열 수 있습니다.
5. 고객이 결제 정보를 입력하고 약관을 확인한 뒤 결제합니다. 승인 결과는 페이앱 서버 통보로 확인합니다.

예약금은 이용료의 일부를 먼저 받는 선결제이며, 이용 후 돌려주는 보증금과 별개입니다. 청구 금액을 바꿔야 한다면 새 링크를 생성합니다. 링크 생성 자체로 고객에게 문자나 알림톡을 보내지는 않습니다.

## 기존 원장과의 관계

- 결제는 기존 `orders`·`payapp_payments` 원장과 승인·부분 환불·전액 환불 검증을 사용합니다. 별도의 수기 수납을 추가하지 않습니다.
- 대관비에서 명시적으로 선택한 기존 예약만 해당 예약의 수납에 연결합니다. 새 결제만으로 일정이나 계약 총액을 바꾸거나 예약을 새로 확정하지 않습니다.
- 출장뷔페·기타는 별도 결제로 기록하며, 참고 예약번호가 있더라도 대관비 수납에 합산하지 않습니다.
- 이번 결제링크 주문의 환불은 결제 원장에 반영합니다. 환불 통보만으로 예약을 자동 취소하지 않습니다. 기존 다른 결제의 취소 정책은 유지합니다.
- 반환 보증금의 입금 확인·환급 계좌·환급 완료 상태를 변경하지 않습니다.

## 중복 요청과 링크 상태

- 관리자 생성 요청의 식별자를 유지해 응답이 늦거나 유실되어도 같은 링크를 다시 찾습니다.
- 링크 하나에 대해 결제 요청은 한 번만 시작합니다. 이미 발급된 결제창은 원래 구매자 연락처로 이어서 열며 새 거래를 생성하지 않습니다.
- 결제 요청 결과가 불명확하면 새 결제 요청을 자동 재시도하지 않습니다. 운영자가 페이앱 거래 내역을 확인해야 합니다.
- 만료·종료는 메가스팟에서 새 결제 접수를 막는 상태입니다. 이미 결제창을 발급한 링크는 일반 종료 대상에서 제외합니다. 페이앱 거래 취소나 환불을 대신하지 않습니다.
- 브라우저의 완료 화면 이동은 승인 근거가 아닙니다. 서명·판매자·주문별 nonce·금액·거래번호가 일치하는 서버 통보만 결제 상태를 갱신합니다.
- 늦게 도착한 승인·환불 통보도 원래 주문과 판매자 계정으로 검증합니다.

## 접근과 배포

관리자 API는 기존 관리자 인증과 같은 출처 검사를 사용합니다. 고객 링크는 추측하기 어려운 임의 토큰으로 접근하고, 고객에게 관리자 메모·결제 비밀키·다른 고객 정보를 노출하지 않습니다. 고객 화면과 응답은 검색 제외·캐시 금지·참조 주소 전송 금지를 적용합니다.

새 `payment_links` 표는 기존 스키마 초기화에 포함됩니다. 배포 후 관리자 목록 조회로 연결을 확인하고, 운영 확인용 링크의 생성·조회·종료를 검증합니다. 이 확인 과정에서 실제 결제창을 발급하거나 결제·취소·환불·고객 발송을 실행하지 않습니다.

페이앱 로고·HTML 설명 지정 필드는 공식 REST 문서에 없으므로 상세 안내는 메가스팟 화면에 표시합니다. 페이앱 결제창은 기존 판매자 설정을 사용합니다.
